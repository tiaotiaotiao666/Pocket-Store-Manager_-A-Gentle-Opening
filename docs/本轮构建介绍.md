# 本轮构建介绍

## 本轮目标

把项目从共用点餐小程序方向调整为 Windows 桌面端生成器：店主按向导配置一家门店，预览视觉方案，再导出属于该门店的独立微信原生小程序工程。

## 已完成内容

- 使用 Electron + React 实现 Windows 桌面端生成向导，覆盖门店资料、功能选择、模板匹配、风格与页面图标、预览与导出。
- 模板缺少所选功能时优先匹配最接近模板；仅标记已验证模块可拼装，其余作为待开发项提示。
- 首版 AI 范围限定为风格推荐和页面图标生成。没有配置云模型时明确显示本地占位演示；华为云图像服务尚待实测，模型密钥保留在服务端。
- 新增原生小程序模板，包含首页、菜单、订单、我的四页，以及门店配置、主题样式和微信开发者工具项目配置。
- 导出目录自动生成门店专属 README，说明如何导入预览、修改门店数据和正式发布所需条件。
- 明确每家店需使用自己的微信小程序账号、主体和 AppID；生成器不代注册、不代审核、不代发布。
- 修复桌面端白屏：Vite 开发模式不能直接运行用于 Node.js 的 CommonJS 目录模块，已将 UI 使用的目录改为 ES module，并调整导出脚本通过动态导入读取。

## 本轮验证

- `npm run build`：通过，Vite 成功构建桌面端前端资源。
- `npm test`：通过，2 项导出测试通过，覆盖工程结构、门店数据、主题色、价格及功能待开发状态。
- `npm run build`（`server/`）：通过，NestJS 服务端编译成功。
- 已检查 Vite 开发服务器实际返回的模板目录模块：包含 ESM 导出，不再包含 `module.exports`。
- Electron 二进制在当前 Windows 环境通过 `electron --version` 检查，版本为 `v33.2.1`。

## 当前边界与后续工作

导出的点餐工程目前是可预览的前端演示模板，不含真实下单后端、登录、支付或店主订单工作台。华为云生图服务的具体产品能力、鉴权和 API 格式尚未验证，不能描述为已完成华为云接入。后续应先在微信开发者工具中验证导出工程，再完善模型服务适配、桌面安装包和线上门店后端。

## 2026-10-31 DeepSeek Agent 首次真实接入

### 目标

把 `STORE_INFO` 阶段的本地 Mock Agent 换成真实链路：

```text
桌面端 → POST /api/v1/agent/turn → NestJS → DeepSeek → 后端校验 → agent-turn.v1
```

本轮不接 ModelArts、盘古、Skill、工具调用、多 Agent、自主规划和数据库写入。

### 已完成

- 后端新增独立 `server/src/agent/` 模块：Controller、Service、类型、**服务端独立草稿校验器**、临时鉴权 Guard、统一异常过滤器、Module。
- 新增 `DeepseekAgentProvider`：调用 `{baseUrl}/chat/completions`，固定 system prompt 约束「只提取、不臆造、不写库、不调工具、只输出 JSON」；支持 Markdown 围栏清洗、超时、上游 401/429/5xx 映射。
- 模型输出只取 `reply` + `draftPatch`；后端按白名单合并（未知字段丢弃、空串不覆盖），再重新计算 `missingFields` / `errors` / `nextQuestion` / `status`，**完全忽略模型返回的同名字段**。
- 缺少 `DEEPSEEK_API_KEY` 返回 `503 DEEPSEEK_NOT_CONFIGURED`，**不回退本地 Mock**；开发环境缺 Key 不阻止服务启动。
- 生产安全：`NODE_ENV=production` 必须 `AGENT_REQUIRE_AUTH=true`；production 或开关为 true 时无 Authorization → 401。DeepSeek Key 永不作为客户端 Token。
- CORS 允许 `X-Agent-Contract`，暴露 `X-Request-Id`；错误体统一 `{ code, message, requestId }`。
- 前端 `agentServiceConfig.js` 支持 `VITE_AGENT_TRANSPORT=mock|http`、`VITE_AGENT_ENDPOINT`、`VITE_AGENT_TIMEOUT_MS`；`agentTurnService.js` 在 http 模式自动创建 `createHttpTransport`，不重写状态机。
- 前端仍以本地 `validateAgentDraft` 为最终确认门槛；失败、重试、输入可编辑行为保持不变。

### 验证

- `cd server && npm test`：**68/68 通过**（validator 29、service 12、provider 16、e2e 11），全部使用 mock fetch。
- `cd server && npm run build`：通过。
- 根目录 `npm test`：**96/96 通过**（原有 91 + 新增 5）。
- 根目录 `npm run build`：退出码 0，1613 modules，CSS 56.12 kB / JS 254.73 kB。
- `VITE_AGENT_TRANSPORT=http npx vite build`：产物包含 `VITE_AGENT_TRANSPORT:"http"`。
- 真实启动：`health` 200、`readyz` 200；无 Key 时 `agent/turn` → 503；契约版本错误 → 400；CORS 预检 → 204。
- **真实 DeepSeek 调用（2026-10-31 补充验证）**：资料完整 → 200 `reviewing`（`meta.model=deepseek-chat`，`latencyMs≈1095`）；仅给店名与品类 → 200 `collecting` + `nextQuestion.field=businessHours`，模型未臆造营业时间。日志确认无 Key / `Bearer` 泄漏。

### 边界

- **真实 DeepSeek 调用已通过**（2026-10-31，测试 Key 仅写入被 git 忽略的 `server/.env`，验证后由用户销毁）；自动化测试仍全部使用 mock fetch。
- **ModelArts / 盘古尚未接入**；当前没有 Skill、工具调用、多 Agent、自主规划和自动发布。
- Agent 仍然**不写业务数据库**；确认前不落库、不复用 B1 `sessions`。
- 未做店主真实登录、幂等、限流、内容审核与会话持久化。
