# 组件入库标准

> 本文定义 UI Block、Feature Pack 进入版本化注册表之前必须满足的契约。
> “必须 / MUST”是不可跳过的门禁；“建议 / SHOULD”是默认做法，偏离时要在审查记录里说明。
> 字段的机器校验以 `templates/registry/schema/manifest.v1.json`、`templates/registry/schema/base.manifest.v1.json` 和 `scripts/composer/` 为准。

## 1. 先判定资产类型

| 需求特征 | 资产类型 | 原因 |
| --- | --- | --- |
| 只展示已有 props，用户意图通过事件上报 | UI Block | 不引入页面与服务边界 |
| 需要新页面、页面级状态、导航或服务调用 | Feature Pack | 页面与服务必须显式声明 |
| 需要换一套现有页面视觉与布局，但保留 Base 控制器 | FrontendPack | 只覆盖 WXML/WXSS/页面 JSON，不生成 JS |
| 需要新的后端接口或数据模型 | 先做后端能力，再做 Feature Pack | 前端资产不得宣称未实现的后端能力 |
| 只是现有组件换颜色、尺寸、文案或落位 | 不新建资产 | 通过 Plan 的 `themeTokens` / `presentationTokens` / `slotOrder` 表达 |

UI Block 的硬边界：`allowNetwork`、`allowRoutes`、`allowGlobalState`、`allowServices` 四项必须全部为 `false`。功能包中也只有页面扩展文件允许调用服务层，组件本身仍不得触网。

## 2. 身份与目录

### 2.1 命名

- 资产 ID：3–48 位 kebab-case，匹配 `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`。
- 版本：精确 `MAJOR.MINOR.PATCH`。禁止 `latest`、`^1.0.0`、`~1.0.0`、`1.x`。
- 目录名必须与 `identity.version` 完全一致。
- `displayName` 不超过 48 个字符。

### 2.2 UI Block 目录

```text
templates/components/<id>/<version>/
├─ manifest.json
├─ src/
│  ├─ index.js
│  ├─ index.json
│  ├─ index.wxml
│  └─ index.wxss
└─ preview/
   ├─ normal.json
   ├─ empty.json
   ├─ error.json
   └─ long.json
```

### 2.3 Feature Pack 目录

```text
templates/features/<id>/<version>/
├─ manifest.json
├─ src/
│  ├─ components/
│  │  └─ <component-id>/index.{js,json,wxml,wxss}
│  ├─ pages/
│  │  └─ <pageId>.extend.json
│  └─ assets/                # 可选，包内本地素材
└─ preview/
   ├─ normal.json
   ├─ empty.json
   ├─ error.json
   └─ long.json
```

`pages/<pageId>.extend.json` 只声明插槽和钩子名，例如：

```json
{
  "pageId": "home",
  "slotId": "home-hero",
  "component": "poster-carousel",
  "hooks": { "onLoad": "attachPosterCarousel" },
  "note": "仅声明插槽与钩子名；实际替换由 Composer 在构建期按锚点完成，运行时不动态加载组件。"
}
```

### 2.4 FrontendPack 目录

```text
templates/frontend-packs/<id>/<version>/
├─ manifest.json
├─ src/
│  └─ pages/
│     └─ <pageId>/index.{wxml,wxss,json}
└─ preview/
   ├─ normal.json
   ├─ empty.json
   ├─ error.json
   └─ long.json
```

FrontendPack 不允许包含任何 `.js`；页面控制器仍来自 Base。Manifest、合并语义与安全门禁见 [`FrontendPack视图包标准与范例.md`](FrontendPack视图包标准与范例.md)。

它不是运行时代码，也不会被 Composer 当作可执行脚本读取。

> **容易踩的坑：** Composer 的复制逻辑以 `features[].slots[]` 的 assignment 为准。只在 Plan 的 `components[]` 中登记一个 UI Block，并不会让它的源码进入导出工程；纯展示组件必须被某个 `features[]` 条目分配到接受 `ui-block` 的合法插槽，或者放在一个 Feature Pack 的组件目录中。

## 3. Manifest 必填字段

`manifest.v1` 要求下列字段全部存在；缺一即拒绝，不允许用默认值补齐：

| 字段 | 类型 | 必须满足 |
| --- | --- | --- |
| `schemaVersion` | string | 固定为 `manifest.v1` |
| `identity` | object | 含精确 `id`、`version` |
| `kind` | string | `ui-block` 或 `feature-pack` |
| `displayName` | string | 不超过 48 字符 |
| `entry` | object | 含 `path`、非空 `files`、`assets` |
| `interface` | object | 含 `props`、`events` 两个数组 |
| `boundary` | object | 四项布尔值齐全；UI Block 必须全为 false |
| `compatibility` | object | 含 `baseRange`、`minWechatLib`、`apiContract` |
| `requiredPages` | array | 页面 ID 均须在 Base Manifest 中声明 |
| `requiresSlots` | array | 只能是 Base 已声明的合法插槽 ID |
| `dependencies` | array | 精确版本；依赖只能是 UI Block 或 Feature Pack |
| `conflicts` | array | 资产 ID 列表 |
| `preview` | object | 含相对 `dir`，且 `kinds` 至少覆盖 `normal/empty/error/long` |
| `release` | object | 含 `stage`、`knownLimits`（以及可选的 `verifiedRecipes`） |

### 3.1 `entry`

- `path` 必须是包内相对 POSIX 路径：不能以 `/` 或 `\` 开头，不能出现 `..`，不能含反斜杠、外部协议或 UNC 路径。
- `files` 必须非空，并且每个文件在 `entry.path` 下真实存在。
- `assets` 中每个文件必须真实存在。Feature Pack 的素材会被复制到导出工程的 `assets/<id>/<basename>`。

### 3.2 `interface`

- `props[].name` 必须是 camelCase，匹配 `^[a-zA-Z][a-zA-Z0-9]*$`。
- `props[].type` 只能是 `string | number | boolean | array | object`。
- 每个 prop 必须有默认值；组件的 `properties` 键集合必须与 Manifest 声明**完全相等**，多声明与少声明都会让 `registry:check` 以 `INTERFACE_MISMATCH` 失败。
- `events[].name` 必须是 camelCase。实现中每个 `triggerEvent` 的名字都要被声明；声明的事件也必须在实现中出现。
- 事件 `payload` 是字段名数组，detail 只应包含这里声明的字段。

### 3.3 `compatibility`

```json
{
  "baseRange": "^1.0.0",
  "minWechatLib": "3.0.0",
  "apiContract": "storefront.v1"
}
```

- `baseRange` 必须是 `^MAJOR.MINOR.PATCH` 形式，并实际满足当前 Base 版本。
- `minWechatLib` 是精确版本，且不得低于 Base 声明的最低基础库。
- `apiContract` 目前只支持 `storefront.v1`；Plan 的 `apiBinding.contract` 必须与之一致，否则 `API_CONTRACT_INCOMPATIBLE`。

### 3.4 `release`

| `stage` | 含义 | 进入条件 |
| --- | --- | --- |
| `candidate` | 候选资产/配方，可供内部预览，不进入正式可选列表 | Manifest 与静态检查通过 |
| `preview-only` | 只能展示，后端能力未实现，不得对外宣称上线 | 必须在 `templates/registry/preview-registry.json` 登记 capability、业务目的、最小契约、优先级和验收标准 |
| `online-ready` | 组件能力可进入 direct Recipe | Manifest、边界、实现一致性、预览数据与编译验证通过 |
| `blocked` | 暂不可用 | 缺口未解决 |

**direct Recipe** 需要四类证据，缺一即 `RECIPE_EVIDENCE_MISSING`：`wechatCompile: "pass"`、`regression: "pass"`、`secretScan: "pass"`、非空 `approvals`。模型不得自行填写 `wechatCompile: "pass"` 或伪造审核记录。

## 4. 组件通信硬约束

组件内部禁止：

1. `wx.request`、`wx.uploadFile`、云函数或任何 API。
2. 读写 `getApp().globalData`、页面栈或其他全局业务状态。
3. `wx.navigateTo` / `wx.redirectTo` / `wx.switchTab` / `wx.reLaunch` 等固定路由。
4. `require` 服务层、页面模块或后端类型。
5. 在组件内登录、授予角色或推断店主权限。

组件允许维护纯 UI 状态（展开、选中、滚动位置），但不得把业务数据副本当成事实来源。数据获取、路由、桌号校验、金额计算和错误处理都属于页面/服务层。

金额只有一个事实：整数分 `priceCents`。禁止在组件或 Plan 中引入 `priceText` / `totalCents` 第二份金额事实（`STORE_CONFIG_FIELD_FORBIDDEN` / `MONEY_SECOND_SOURCE`）。

## 5. 插槽契约

当前 Base 声明四个插槽：

| 插槽 | 页面 | 容量 | 接受类型 |
| --- | --- | --- | --- |
| `home-hero` | `home` | 1 | `feature-pack`、`ui-block` |
| `home-marketing` | `home` | 2 | `feature-pack` |
| `menu-aside` | `menu` | 1 | `ui-block` |
| `menu-hero` | `menu` | 1 | `feature-pack`、`ui-block` |

插槽以 Base Manifest 的 `slots` 为准；`slots.json` 是人类可读镜像，当前尚未列出 `menu-hero`，新增或调整插槽时应同步更新。

每个可插拔组件必须在自己负责的页面 WXML 中保留完整的三段式锚点，Composer 只替换 fallback 区间：

```xml
<!-- @slot:home-hero -->
<!-- @slot-fallback:home-hero -->
<store-header ... />
<!-- @slot-fallback:home-hero:end -->
<!-- @slot:home-hero:end -->
```

未分配插槽时，Base 页面必须继续完整运行；导出工程不得残留未使用组件。

`requiresSlots` 非空的资产，使用它的 Plan 必须在 `features[].slots[]` 中提供对应声明；若要移动落位，只能通过 Plan 顶层 `slotOrder` 覆盖 assignment key，不能改写 `features[].slots[]`，否则会触发 `SLOT_REQUIRED_MISSING`。

## 6. 预览数据

每个资产必须提供四类可解析 JSON：

- `normal`：完整、合法的正常数据。
- `empty`：空列表/空对象/空字符串等空态，但仍满足 prop 类型。
- `error`：加载失败、禁用、不可售等异常展示。
- `long`：超长文案、超大数量、极端比例，用于检查截断与溢出。

预览数据只用于展示与回归，不得包含秘密、绝对路径、内网地址或外部 URL。`registry:check` 会对非 Base 资产按 production 模式扫描，命中 `SECRET_DETECTED` / `PATH_ESCAPE` / `INTERNAL_ADDRESS` / `EXTERNAL_URL` 会失败。

## 7. 素材与媒体

- 组件只能引用候选包内的本地素材，禁止外链。
- 每个图片素材需要声明用途、宽高比、建议尺寸、数量、是否必需、缺图兜底行为，以及是否允许用户上传或模型生成。
- 图像/视觉模型只能提供候选素材；生成失败时使用明确标注的占位图，不能伪造已生成。
- `entry.assets` 声明的文件必须存在；否则以 `ENTRY_MISSING` 拒绝。

## 8. 版本与发布门禁

### 8.1 入库前

1. 新 ID 或新版本不得与注册表已有版本冲突。
2. Manifest 四项边界符合类型要求。
3. 组件 `properties` 与 `triggerEvent` 和 Manifest 双向一致。
4. 预览数据四类齐全且可解析。
5. 资产目录整体扫描无敏感内容。
6. 若为 `preview-only`，必须先在 `preview-registry.json` 登记。
7. 若涉及首页营销、广告位、优惠券的扩展顺序，确认 `templates/registry/expansion-order.json` 未被跳过。

### 8.2 入库操作

```powershell
# 先登记到 templates/registry/registry.v1.json（integrity 可先留占位）
node scripts/registry-check.cjs --write   # 按真实内容重算摘要并冻结
npm run registry:check                    # 校验 Manifest、入口、预览、边界与晋升证据
npm test                                  # 含 test/composer-assets.test.cjs
```

不要手写 `integrity`，也不要在多个并行任务中各自修改 `registry.lock.json`。

### 8.3 晋升

- 先以 `candidate` 进入注册表。
- 至少有一份 Recipe 能真实引用它并生成工程。
- 微信开发者工具编译通过、核心闭环回归通过、敏感信息扫描通过后，才可填写 `approvals` 并晋升 `direct` / `online-ready`。
- 资产或素材内容变化后，旧截图立即视为过期，必须重新生成并重新冻结。

## 9. 审查清单

- [ ] ID / 版本 / 类型符合命名规则，目录版本一致。
- [ ] Manifest 必填字段齐全，未出现禁止键。
- [ ] `entry.files`、`entry.assets` 与磁盘一致。
- [ ] UI Block 边界四项全为 false，组件无顶层副作用、无触网、无固定路由、无全局状态、无服务层依赖。
- [ ] props 名称、类型、默认值与实现双向一致。
- [ ] 事件名称、payload 与实现双向一致。
- [ ] 四类预览数据齐全并可解析。
- [ ] 每个 `requiresSlots` 都有对应的合法落位。
- [ ] 至少一份 Recipe 真实使用并成功生成。
- [ ] `registry:check` 与 `npm test` 通过，证据路径可追溯。
