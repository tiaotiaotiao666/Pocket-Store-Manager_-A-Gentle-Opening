# 后端实现方案与套餐

> 本文统一后端范围、阶段顺序和可选实施套餐。API 字段以 `docs/api.md` 为准，订单规则以 `docs/order-state.md` 为准；本文件负责说明先做什么、如何实现以及每个套餐交付什么。若文档冲突，先修订契约再实现。

## 1. 统一后的产品路线

项目分为三个有先后依赖、但可以独立交付的部分：

1. **桌面生成器**：本机配置门店、选择已验证模板和风格、生成并导出独立小程序工程。当前已有本地导出和服务端模型代理。
2. **点餐业务后端与小程序**：使用 `/api/v1` 为门店目录、顾客订单和店主工作台提供在线能力。这是首个后端交付主线；先完成演示环境闭环，再决定是否进入正式营业部署。
3. **生成器云端协作能力**：项目/会话持久化、动态目录、模板候选、生图任务和部署任务。属于独立后续阶段，不阻塞点餐闭环；当前桌面 UI 可继续使用本地导出和演示占位。

首期范围为**单套服务、多门店按 `storeId` 隔离**，跑通「运维预置门店和店主 → 顾客扫码浏览 → 创建订单 → 演示模拟付款 → 店主处理订单」。生成器向业务后端导入配置属于后续套餐。真实微信支付、退款、配送、公开店主注册、自动审核发布均不在首期范围。

现状：`server/` 只有 NestJS 启动、`GET /health` 和图像/风格模型代理；没有业务模块、数据库、Redis 或微信登录实现。`docs/后端待实现接口清单.md` 仅描述第 3 部分，不是首期点餐 API 清单。

## 2. 技术和分层建议

- **运行时**：Node.js 22 + NestJS 11，沿用 `server/` 当前版本。
- **持久化**：MySQL 8；建议 Prisma 管理 schema、迁移和类型安全查询。金额用整数分；订单保存商品名称、单价等下单快照。
- **缓存**：Redis；首期只缓存菜单目录并支持版本和失效。订单、状态历史和幂等记录以 MySQL 为准。
- **认证**：服务端用微信 `code` 换 OpenID；开发演示通过显式环境变量启用 demo 登录。发放有过期时间的服务端会话 Token；OWNER/STAFF 只从数据库 membership 读取。
- **API**：保持 `docs/api.md` 的 `/api/v1`、camelCase、统一错误结构、UTC 时间、整数分金额和租户隔离约定。
- **校验与安全**：DTO 白名单校验、统一异常过滤器和 `requestId`、启动时配置校验、按环境配置 CORS。密钥只存在服务端环境/密钥管理系统，不进入前端、导出工程或日志。
- **测试**：服务层单测、API 集成测试、MySQL/Redis 契约测试；订单状态机 S1–S12 作为交付门槛。

建议模块：`auth`、`users`、`stores`、`catalog`、`orders`、`merchant`、`database`、`cache`、`common`。Controller 负责 HTTP/DTO，Service 实现用例和权限，Prisma 负责存取；订单跨表写入在一个数据库事务内完成。

## 3. 分阶段实现计划

### B0：契约与演示数据冻结

- 对齐 `docs/api.md` 与 `docs/order-state.md` 的字段、状态和错误码；标注 API 与 `template-schema` 版本。
- 明确 demo 门店、桌号、菜单、预绑定店主和演示用户身份；绑定通过服务端种子/运维流程完成，不开放客户端授予角色。
- 补齐 `server/.env.example`、本地运行说明、MySQL/Redis 开发环境说明。
- 验收：新环境可启动依赖、迁移和种子；健康检查成功；生产配置拒绝 demo 开关。

### B1：业务后端最小闭环

- 实现 `auth`、`stores`、`catalog`、`orders`、`merchant` 及通用错误处理和权限守卫。
- 按契约实现登录/me、公开门店和目录、创建/查询订单、演示付款、店主订单列表/状态推进、商品上下架。
- 下单事务内重新校验门店、桌号、可售商品，以数据库价格计价；合并重复商品 ID；保存订单项快照、初始状态日志和幂等记录。
- 状态更新先校验合法转换，再使用 `WHERE status = expectedStatus` 条件更新；同一事务写状态日志。并发冲突不得产生部分记录。
- 商品上下架更新目录版本，提交后失效 Redis；目录只返回可售商品。
- 验收：S1–S12 全过，权限/租户测试通过；重复下单不重复创建；停售后旧订单快照不变。

### B2：小程序接入与端到端演示

- 建立统一 API service，封装请求、Token、错误归一化、超时和重新登录；页面不各自处理 HTTP。
- 接入扫码 `scene` 的 `storeId/tableId`、顾客菜单/结算/订单详情、演示模拟付款和店主订单台。
- 创建订单时生成并持久化本次 `Idempotency-Key`；重试复用，完成或放弃后才更换。客户端不发送价格或总价。
- 验收：微信开发者工具完成从扫码到店主完成订单的演示；模拟付款界面标注“演示模拟支付”。

### B3：生成器接业务后端

- 增加受控的门店配置导入/初始化，将配置校验后写入门店、分类、商品和桌号；重复导入需防重并避免覆盖运营数据。
- 导出模板只写公开 API Base URL 和 `storeId`；不写任何 AppSecret、Token、数据库或模型密钥。
- 将 `schemaVersion` 映射到后端配置版本；不兼容版本拒绝并返回可读错误。
- 验收：重复导入行为确定、变更可审计、生成工程指向正确门店。

### B4：云端发布与运维

- 先在可复现容器环境跑通，再接 RDS、DCS、ECS/容器、HTTPS/API Gateway、日志和备份。
- 单独验证图像服务的产品能力、区域、鉴权和响应格式；保留 provider adapter。未经真实探测不得显示“已接入”。
- 配置生产域名、TLS、CORS、微信合法域名、隐私说明、限流、监控和恢复演练。
- 验收：备份恢复、健康探测、敏感信息扫描、部署回滚和端到端证据齐全。

### B5：桌面生成器云端能力（独立排期）

- 范围以 `docs/后端待实现接口清单.md` 为准：项目/会话持久化、固定引导脚本、功能/模板/风格目录、候选生成、提示词轮次、生图异步任务和部署任务。
- 项目与图片按 owner 隔离；长任务使用持久化状态和队列 worker，MySQL 保存任务和结果，Redis 加速进度/短期状态；图片存对象存储并用短时签名 URL。
- 先交付持久化与目录，再接模型工作流；密钥只由服务端读取。生成器部署最多生成工程并上传演示环境，不代替店主向微信平台发布。
- 验收：刷新恢复项目和会话、任务可查且失败可重试、图片有迭代历史、用户间不可访问、无模型配置时状态准确。

## 4. 实施套餐

以下估算按 1 名熟悉 NestJS/微信小程序的全栈工程师计算，含基本评审和自动化验证，不含微信资质、云账号审批、备案或供应商支持等待时间；并行投入会改变日历周期。

| 套餐 | 交付范围 | 参考投入 | 适用场景 | 不包含 |
| --- | --- | --- | --- | --- |
| **A. 后端核心包（推荐起步）** | B0 + B1；本地/测试 MySQL、Redis、迁移/种子、首期业务 API、S1–S12 自动化测试 | 约 2–3 人周 | 先建立可验证的后端业务闭环 | 小程序页面接入、生成器导入、云上线 |
| **B. 可演示闭环包（推荐首个完整里程碑）** | A + B2；顾客端和店主端调用真实 API，微信开发者工具端到端演示 | 约 4–6 人周 | 答辩或产品验证，需要扫码到出餐演示 | 真实支付、正式生产 SLA、生成器云端会话 |
| **C. 门店配置联通包** | B + B3；生成器配置导入、多门店初始化、导出工程连接在线门店 | 约 1–2 人周增量 | 生成器产物要成为在线门店菜单 | 自助注册、在线改价/商品管理 |
| **D. 云部署加固包** | C + B4；目标云部署、TLS、监控/备份/恢复、供应商模型验证与部署流水线 | 约 2–4 人周增量，另计云资源 | 受控试点或正式环境准备 | 微信支付、外送、自动审核发布 |
| **E. 生成器云端协作包** | B5；项目/会话存储、提示词/图像任务、对象存储与任务查询 | 约 3–5 人周，模型供应商集成另评 | 桌面工作台需要跨设备/刷新恢复 | 点餐闭环强依赖、自动生成业务代码 |

**推荐顺序**：先 A，再以 B 作为首个完整验收目标；确认在线配置同步需求后加 C；试点环境、账号和域名具备后再做 D。E 独立立项，避免桌面会话持久化拖延点餐闭环。

## 5. 实施默认值与待确认项

当前建议默认值：

1. 登录采用真实微信 `code` 登录；开发使用 `ALLOW_DEMO_LOGIN=true` 和预绑定 demoOpenId，生产拒绝 demo 登录。
2. 首期为多门店 SaaS 形态（单服务按 `storeId` 隔离），不是每店独立部署后端。
3. 首期 MySQL + Redis；本地容器开发，云上映射 RDS/DCS。
4. 菜单由种子/生成器导入维护；首期不提供公开商品创建、改价和删除 API。
5. B 套餐交付演示环境，不视为可承载真实营业；真实支付和正式营业合规另行评审。

实施前请确认是否接受以上默认值，以及：演示门店/店主绑定方式、目标微信账号和云资源是否已有、首个里程碑选 A 还是直接做 B。未确认前可按默认值完成 B0 设计，但不应开启生产云部署。
