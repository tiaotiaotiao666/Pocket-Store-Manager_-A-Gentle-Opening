# 模板页「不满意 → 重新用语言描述」构建说明（2026-11-03）

> 面向：后续接手本仓库的 AI / 开发者。
> 本文自包含，不依赖本轮对话上文。所有命令均在仓库根目录执行（Windows，git-bash）。

## 1. 本轮目的与范围

用户截图反馈：模板匹配结果页只有「对于当前页面满意？→ 下一步」，**没有「不满意 → 重新用语言描述」的入口与对话框**。自然语言生成模板必然存在匹配不上的情况，缺少重描述入口等于逼迫用户接受不合适的结果，与产品「用自然语言描述即可搭建小程序」的 Agent 定位直接冲突。

本轮范围（只做这些）：

- 在 `TEMPLATE_PICK` 阶段（`TemplateGallery` 详情面板）增加自然语言重描述输入区；
- 提交后**不离开模板页**：当前会话追加用户消息与 agent 回复，候选原地重建，保留上一版候选直到新版返回；
- 让描述**真实影响匹配结果**（关键词命中重排 + note 写明命中词），而不是只存一句备注假装理解；
- 失败、空候选、重复提交都有明确状态；
- 重描述文本随 `project.json` 持久化，重开项目后不丢上下文；
- 把「模板推荐改走后端 Agent」写成待实现接口建议，不阻塞本轮。

本轮**不做**：后端 Agent 接入、真实大模型模板推荐、模板阶段风格切换、视觉走查截图。

## 2. 交互流程

```
模板页（TEMPLATE_PICK）
  ├─ 选骨架（点卡片）                → SELECT_TEMPLATE，实时预览跟着换
  ├─ 不满意：输入一句话 + 点「重新匹配骨架」 → SUBMIT_TEMPLATE_FEEDBACK
  │      ├─ 用户消息进入当前会话
  │      ├─ agent 回复「收到，我按你的描述重新排了一遍…」
  │      ├─ build.status = building（详情区按钮变「重新匹配中」+ spinner）
  │      └─ buildTemplateCandidates(...) → TEMPLATE_REBUILD_READY（原地替换候选）
  │             └─ 失败 → TEMPLATE_REBUILD_FAILED（保留旧候选 + 红色错误提示 + 会话追问）
  └─ 满意：点「下一步」               → CONFIRM_TEMPLATE（进入店铺装修会话）
```

约束：

- 重描述**不清空**已选功能、已选模板、已有候选；
- building 期间重复提交被忽略（避免并发覆盖）；
- 「下一步」在 building 期间禁用，避免用旧候选进入下一阶段；
- 描述为空不生效；超长按 `TEMPLATE_REFINE.maxLength = 300` 截断；
- 累积描述最多保留最近 8 条。

## 4. 状态与数据

```js
// state.build（模板阶段）
{
  status: 'idle' | 'building' | 'ready',
  candidates: Candidate[],       // 重建期间保留上一版
  selectedId: string | null,
  feedback: string[],            // 累积重描述，最多 8 条
  refineError: { code, message } | null,
}
```

`Candidate` 本轮新增字段：

- `briefHits: number`：命中描述关键词个数（0 时 UI 不显示标签）；
- `briefKeywords: string[]`：命中的具体词，用于 note 文案与后端对接时的可解释性。

`note` 规则（如实，不做假装理解）：

- 描述命中 → `已按「…」调整：命中 招牌菜、大图`
- 描述未命中任何词 → `已按「…」重新排序；这条描述里没有可识别的风格词，仍以功能匹配为先。`
- 无描述 → 沿用模板 `summary`

## 6. 未验证 / 已知边界

1. **人工视觉走查未做**：本轮只完成自动化测试与构建，未截图确认输入区在桌面端的真实观感与焦点态。验收判据是界面上可见的入口，不是测试通过。
2. **模板推荐仍未走 Agent**：`buildTemplateCandidates` 是本地关键词规则。它会在 note 里如实写明命中词，但**不能宣称「模型理解」**。真实模型接入见 `docs/后端待实现接口清单.md` §5.1。
3. **关键词表是显式枚举**（`catalog.mjs` 的 `keywords`），覆盖面有限；用户描述里的同义词未命中时会走「没有可识别风格词」的分支，属于设计内的诚实降级，不是 bug。
4. **持久化字段版本兼容**：`project.json` 的 `build` 新增 `feedback`，旧文档缺失时 `pickBuild` 补 `[]`，向后兼容；但 `build` 切片目前没有独立 schemaVersion，若后续再加字段需沿用同一「缺省补默认值」策略。
5. **未做**：模板阶段风格切换（既有待拍板项）、重描述历史列表/回退到某一版候选。

## 7. 给后续 AI 的注意事项

- 改 `App.jsx` 后先跑 `node --test test/app-imports.test.cjs`（仓库曾因未导入标识符导致白屏/卡死）。
- 新增模板关键词时只动 `catalog.mjs`，不要把匹配逻辑复制到组件里；组件只收属性发事件。
- 若要接入后端，只需替换 `agentService.buildTemplateCandidates` 的实现并保留返回字段形状（`briefHits` 可缺省），前端 UI 不需要改。
- 会话消息是用户可见的证据链：`SUBMIT_TEMPLATE_FEEDBACK` 必须同时写入用户消息与 agent 回复，否则会出现「点了没反应」的错觉。
