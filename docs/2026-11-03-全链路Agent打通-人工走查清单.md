## 1. 对话 → 模板候选（真实模型）

1. 首页「轻启」新建一个项目（或复用空项目）。
2. 输入：店名「松月食堂」、品类「面馆」、营业时间「10:00-21:00」、取餐方式「到店自取」。
3. 观察右栏预览是否随草稿逐步出现（缺项阶段允许部分草稿）。
4. 确认资料 → 选择功能 → 进入模板页。

**通过标准**：模板页出现 3 套候选（warm-bistro / modern-coffee / signature-kitchen），每套有理由；理由来自服务端而不是固定文案；响应 `meta.mock=false`（若显示「本地 Mock 演示」徽标则本步 FAIL）。

## 2. 三套模板切换 + 并排对比

1. 依次点击 3 套候选，观察右栏预览按 layout 变化（menu / catalog / editorial）。
2. 进入对比模式，选 2 套，确认并排显示；关闭对比后回到单栏。

**通过标准**：切换无白屏、无控制台未捕获异常；对比模式最多 2 个 `mini-phone`；窄窗口下退化为上下堆叠。

## 3. 对话式修改模板（本轮核心）

1. 在模板页输入：「主色换成墨绿，商品卡小一点，把首页海报挪到菜单页」。
2. 观察：忙碌态 → 成功后面板逐条列出 before→after 变更。
3. 观察右栏预览：主色变墨绿、商品卡变小、海报出现在「菜单」tab 顶部、首页不再有海报。
4. 按 `Ctrl+Z` 撤销一次 → 预览回到修改前；`Ctrl+Shift+Z` 重做 → 再回来。
5. 再输入一次非法请求（例如让 Agent「新增一个广告组件」），确认被拒绝且有可读错误，**预览不得变成空白或错误结构**。

**通过标准**：变更清单至少包含 `theme.primaryColor`、`sizes.productCard`、`slotOrder.poster-carousel` 三类；撤销/重做真实生效；非法请求整包拒绝且保留上一版。

## 4. 传图 + Agent 填表

1. 在店铺资料页上传 1 张菜单照（≤2 张、单张 ≤400 KiB）。
2. 上传 1 张门店环境照（≤1 张）。
3. 触发生成草稿，观察：菜单照生成菜品（菜名/价格整数分/描述），环境照**不生成菜品**。
4. 手工修改一个菜名与价格（价格必须由用户输入整数分，Agent 不得编造）。
5. 观察右栏预览同步更新。

**通过标准**：`vision.menuImages=1`、`vision.storeImages=1`、`vision.analyzed=true`、`vision.degraded=false`；菜品条目可编辑；环境照不产生菜品；超限时前端给出可读错误且**不发请求**。

## 5. 风格 + 提示词 + 生图占位

1. 确认资料 → 选择风格。
2. 生成提示词：检查结构是否按 template layout 分段（主体/构图/色调/光源/留白/禁止项/门店事实），并包含 4 条禁止项。
3. 生成图片：确认标注为本地占位（`local-demo`），**不得出现「AI 已生成」之类文案**。

**通过标准**：提示词 ≤1200 码点；禁止项完整；占位图标注诚实。

## 6. 导出 + 真实渲染截图回传

1. 导出工程到本地目录。
2. 点击「在微信开发者工具打开」，确认外部 IDE 打开了该目录。
3. 在微信开发者工具中编译，截图（含首页与菜单页）。
4. 回到应用，点击「选择截图」，回填两张截图。
5. 对比 React 预览与真机截图：记录差异（尺寸、间距、字体、tabBar）。

**通过标准**：导出工程可被微信开发者工具成功编译；截图回填成功；差异清单已记录（允许有差异，但必须逐条列出，不得写「基本一致」糊弄）。

## 8. 常见阻塞与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `server:dev` 启动即退出 `P1001` | 3306 未监听 | 按 `docs/backend-local-dev.md` 拉起 MySQL |
| 设置页自检 Agent 失败 | endpoint 是相对路径，或后端未起 | 改绝对地址 `http://127.0.0.1:3000`，确认 3000 监听 |
| 模板页显示「本地 Mock 演示」 | transport 仍是 mock | 设置页切真实模型并保存 |
| 微信 IDE 卡 AppID 校验 | `proxyType=SYSTEM` 跟随代理 | IDE 设置改「直连」 |
| 3000 被旧进程占用 | 旧 `dist/main` 未退出 | `Stop-Process` 后重起，改源码不生效时要重启主进程 |
