# P5 答辩说明

## 1. 背景与问题

餐饮小店要做小程序，通常要经历「找人写、反复改、交付一个看不懂的工程」三步，成本高、不可控。本项目把它变成**会话式生成**：店主用自然语言描述门店与菜品，客户端把需求变成一份被校验、被摘要锁定的工程计划，最后由确定性 Composer 生成完整小程序工程。

一句话定位：**AI 负责理解，规则负责生成，人在关键节点确认。**

## 2. 架构

```
Electron 客户端（React + Vite）
  ├─ 会话状态机：home → onboarding → features → building → template-pick
  │                 → store-info → prompt-studio → image-review → deploy
  ├─ 服务端 Agent 调用（POST /api/v1/agent/run，契约 agent-run.v1）
  ├─ 模板注册表（templates/**，带摘要冻结）
  └─ 主进程 IPC：项目读写、导出、AppID 回填、预览、诊断
NestJS 服务端（server/）
  ├─ Agent 编排：模型调用 + 工具白名单（读/写门店资料、校验、图片输入）
  ├─ Prisma + MySQL：门店、分类、菜品、桌台、海报模板
  └─ readyz：数据库与缓存真实探活
Composer（scripts/composer）
  └─ plan.json → 校验 → 生成工程 → output-lock/report 摘要
```

关键设计：**模型不直接写文件、不直接写库**。模型只能产出结构化的草稿；落库与生码分别由白名单工具和 Composer 完成，且 Composer 的输入是一份可被摘要校验的 plan。

## 3. Agent 的工具调用

- 一次门店资料填写实测：`modelCalls=3`、`toolCalls=2`（读取门店资料 → 更新门店资料 → 校验信息），全部成功，草稿从 0/5 到 5/5。
- 工具集是白名单：读门店资料、写门店资料（带字段级校验）、校验资料完整性、图片输入（识别）。没有「执行任意代码」「任意写文件」这类工具。
- 每一次运行都有 `requestId` 与 `runId`，日志里可回放 `status / stopReason / modelCalls / toolCalls / failedTools`。

## 4. 白名单与安全边界

| 边界 | 做法 |
| --- | --- |
| 模型输出 | 只作为草稿，字段级校验（长度、取值范围、必填） |
| 工具 | 白名单，无任意执行能力 |
| 跨域 | 服务端 `allowedHeaders` 显式列举；有回归测试防止漏项（本轮就修过 `X-Request-Id` 缺失导致真实 POST 被拦） |
| 导出 | 只写用户选择的本地目录，不联网、不上传、不发布 |
| 密钥 | 只在 `server/.env`，不进前端、不进导出工程、不进仓库 |
| 能力勾选 | 「导入微信开发者工具」等外部能力必须人工确认，界面不代替你点 |

## 5. 项目恢复

- 每个门店一个项目目录，资料、图片、会话、导出进度全部本地落盘。
- 实测：关闭客户端并重启后，项目列表仍是 12 个项目，打开其中一项回到上次阶段（店铺装修）与已保存的门店名。
- 项目保存有 flush 守卫：退出前会把未落盘的会话状态刷掉，避免「关窗口丢进度」。

## 6. 真实验证结果（详见证据索引）

- 桌面主流程 CDP 真实点击走查：**13 项 PASS / 0 FAIL / 2 BLOCKED**（生图未接入、导出需原生对话框）。
- 重开恢复：3 项 PASS。
- 导出：Composer 真实产物 138 文件，`output-lock.json` 与 `appid-postprocess` 双重摘要校验通过；写真实 AppID 后 `verified: true`。
- 回归：`npm test` 789/789；vite 构建通过；注册表 / 组件目录 / 小程序镜像 / 镜像一致性全部通过；服务端构建通过，19 个套件 296 项通过，6 个数据库套件因账号无 `CREATE DATABASE` 权限在准备阶段失败（前置条件已写清，未隐藏）。

## 7. 局限（不粉饰）

1. **生图未接入**：海报素材一步无真实图像生成，界面如实说明。
2. **参考截图识别依赖上游视觉模型**：本次实测上游 502，界面如实报错、不产假候选。
3. **导出到指定目录需要原生对话框**：自动化走查只能点到按钮，无法在系统对话框里选目录；已在命令行用同一 Composer 通道复核产物。
4. **数据库测试前置**：需要可建库的 MySQL 账号。
5. **真机/发布未验证**：未真机预览、未发布体验版。
6. **华为云未开通、未验证，非本次演示依赖。**
7. **支付是演示模拟**（`DEMO_PAID`），无真实支付通道。
8. 设置文件读取失败时会弹「已保留备份并恢复默认设置」——功能不阻断，但提示文案偏技术化，后续要改。

## 8. 后续规划

1. 接入真实生图服务，把海报素材从「可跳过」升级为「可生成 + 可重生成」。
2. 视觉识别做多供应商降级（主备模型 + 超时退避），把 502 从失败变成可重试。
3. 导出目标目录支持「记住上次位置 + 命令行/配置文件指定」，减少人工点击。
4. 数据库测试提供容器化 MySQL 或临时账号，做到 CI 全绿。
5. 华为云与真实支付作为独立里程碑，先做沙箱与合规评估，再谈接入。
