## 1. 完成范围

按 `docs/api.md` v1.1 与 `docs/order-state.md` 实现了 `common → auth → stores/catalog → orders → merchant` 六个模块：

- 统一错误体 `{code,message,requestId,details?}` 与 `X-Request-Id`。
- demo / 微信登录、`/auth/me`、opaque session（库中只存 SHA-256）。
- 公开门店与可售目录、`catalog:{storeId}` 缓存与版本失效。
- 创建订单（服务端计价、快照、幂等）、模拟付款、顾客取消、列表与详情。
- 店主订单台、合法状态推进、商品上下架与含下架商品的商品列表。

## 3. 本轮暴露并修复的问题

`.env` 曾覆盖真实进程环境变量：测试注入的 `CACHE_DRIVER=memory` 被 `.env` 的 `redis` 覆盖，导致无 Redis 环境启动失败。已在 `validateEnv` 中改为「进程环境变量优先」，符合 dotenv 语义，同时修复了容器部署的同类隐患。

## 4. 遗留问题

- 真实微信 `jscode2session` 未用真实凭据验证；只有代码路径与可注入 fetch。
- 无限流实现；`429 RATE_LIMITED` 仍是契约预留。
- Agent 鉴权仍是独立简化 Guard，未复用 `SessionAuthGuard`。
- 本地开发库保留了联调订单，后续演示前需按运维流程清理。
