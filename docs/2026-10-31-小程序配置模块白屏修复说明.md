# 小程序白屏修复说明（配置模块 JSON → JS）

日期：2026-10-31
影响范围：`templates/mini-program/`、`scripts/generate-mini-program.cjs`、导出的静态小程序工程、生成器测试与模板契约文档。

## 1. 现象

微信开发者工具打开 `generated-projects/松月食堂` 后，模拟器只显示导航栏与 tabBar，四个页面内容全部空白。控制台首条错误为：

```text
module 'config/store.generated.js' is not defined, require args is './config/store.generated'
    at app.js:1
```

随后出现：

```text
Page "pages/home/index" has not been registered yet.
Page "pages/menu/index" has not been registered yet.
Page "pages/orders/index" has not been registered yet.
Page "pages/mine/index" has not been registered yet.
```

## 2. 根因

微信小程序的 `require` 只解析 `.js` 模块：无后缀路径会被补成 `store.generated.js`。旧实现把门店配置写成 `config/store.generated.json`，页面却按无后缀路径 `require('../../config/store.generated')` 引入，模块解析必然失败。

失败链路：

1. `app.js` 第 1 行 `require('./config/store.generated')` 抛错 → `App()` 未执行。
2. 四个页面模块同样抛错 → `Page()` 未注册。
3. 框架仍渲染 `app.json` 声明的导航栏和 tabBar，因此表现为“tabBar 正常、页面内容空白”。

这不是样式问题，也不是基础库版本问题；开发者工具日志里出现的“基础库 3.17.6 首次下载耗时/ECONNRESET 重试”只是首次加载环境的耗时噪声，与白屏根因无关。

## 3. 修复方案

把门店配置从 JSON 文件改为 CommonJS 模块，保持页面代码里的无后缀 `require('.../store.generated')` 不变：

```js
// config/store.generated.js
module.exports = {
  schemaVersion: 1,
  store: { ... },
  catalog: [ ... ],
};
```

生成器负责输出上述模块；模板目录、两个已存在的导出产物同步替换，并删除旧 `.json`。
