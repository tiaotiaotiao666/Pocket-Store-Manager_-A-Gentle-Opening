## 1. 本轮目的与完成范围

本轮把 `STORE_INFO` 阶段已接受的 `agent-turn.v1` 草稿接入唯一 React 预览 ViewModel，使店主无需先确认草稿，就能看到店名、品类、营业时间、履约方式和菜品的安全投影；同时保持确认、导出、本地项目快照和请求生命周期边界不变。

本轮交付包括：

- `CompositionPlan` 店名来源增加预览专用 `draft-first` 选项，导出默认仍为 `confirmed-first`。
- 新增纯白名单 `PreviewViewModel` 与 session selector，compact/full、不同模板候选共享同一展示事实。
- `MiniProgramPreview` 改为只消费 `viewModel` 与 `size` 的展示组件，保留三种布局、四种 tab、主题色和既有 CSS class。
- App、TemplateGallery 与 reducer 完成接线；每次新 turn/retry 使用进程内单调 `requestId`，过期 success/failure 不改变状态。
- 补充领域、结构和跨边界集成测试，修正文档中“本地保存等于后端写库”的混淆，并登记 `agent-turn.v2` 后端建议。

## 2. “实时”的准确定义与数据流

本轮“实时”仅指：**完整响应体接收，经现有 transport、normalize/validate 校验，并由当前请求的 `AGENT_TURN_SUCCESS` 接受后，本地 reducer 更新草稿，React 在下一次提交中重新投影预览。**

数据流为：

```text
agent-turn.v1 完整响应
  → requestAgentTurn normalize / validate
  → 当前 requestId 的 AGENT_TURN_SUCCESS
  → state.agentDraft
  → buildSessionPreviewViewModels(state)
  → buildPlanFromSession(state, { storeNameSource: 'draft-first' })
  → PreviewViewModel
  → MiniProgramPreview
  → React DOM
```

因此：

- 不等待店主点击确认，也不以 `readyForReview=true` 为预览门槛；`collecting` 的安全部分草稿同样可投影。
- 不包含模型网络等待，不要求 token/SSE 流式渲染，不把网络耗时算作本地 React 更新耗时。
- `requesting`、当前请求失败或响应校验失败时，保留最近一次已接受草稿及其预览。
- success/failure 的活动请求身份不匹配时，reducer 返回原 state；草稿、预览、消息、错误与 attempts 均不被该晚响应改写。
- 手动编辑未确认草稿使用同一投影；非法菜品、金额、营业时间和颜色不能绕过白名单约束。

## 3. 预览行为与安全边界

### 3.1 唯一 ViewModel

`preview-view-model.v1` 从 `CompositionPlan.storeProfile/themeTokens` 和固定白名单常量生成。草稿只用于对齐菜品 React key，不用草稿值覆盖 Plan 已规范化的展示值。

- 店名预览使用 `draft.storeName || store.name || '我的餐馆'`；导出仍优先 confirmed `store.name`。
- 菜品只接受非空名称和 `1..999999` 的整数 `priceCents`，显示金额由整数分格式化；不读取 `priceText` 作为金额事实。
- 无合法菜品时使用四个明确的示例商品；示例商品、hero 文案和演示订单不代表后端真实数据。
- 营业时间只展示合法 `HH:MM-HH:MM` 段，多段用中文逗号连接；缺失时显示待完善文案。
- STORE_INFO 使用的 compact 预览在既有 `mini-compact-head` 的 `small` 文案中直接渲染 `store.businessHoursText`，与 full 的 MineTab 读取同一 VM 字段；不再只让 full 展示营业时间。
- compact/full 消费同一 VM，只允许商品数量和布局密度不同；`selected` 与当前 `byTemplateId[id]` 是同一对象。
- 商品优先使用本地菜品 ID，缺失时使用名称与整数分组成的回退 key，并对重复 key 稳定去重；不使用数组下标作为 key。
- 主题只接受七项 `#RRGGBB` token，非法项回落到既有 warm-orange 预设；图标只从固定 lucide 白名单映射。

### 3.2 能力范围

本轮 Agent 实时闭环**仅覆盖 `STORE_INFO` 的 Web React DOM 视觉近似预览**。`TEMPLATE_PICK` 只复用既有模板切换能力和重构后的组件，不表示 Agent 已能修改模板、主题或布局。

该预览不是 WXML/WXSS，不是微信运行时，不是原生编译结果，也不能据此证明真实小程序端像素一致。商品缩略图仍为主题渐变，未接入 Agent 提供的任意图片或 URL。

## 4. 确认、本地快照与后端发布边界

这三个边界必须分开理解：

| 边界 | 当前行为 | 不表示什么 |
| --- | --- | --- |
| 本机草稿快照 | 既有 `project.json`（`schemaVersion=1`）可保存未确认 `agentDraft`、会话消息、`agentConfirmedSeq` 等既有字段；重新打开后可恢复并投影 | 不表示后端已确认、已写业务库或已发布 |
| 本地保存调度 | 既有自动保存、防抖与 pending flush 继续工作；重置、切换或重新打开等路径沿用既有 flush 与消息顺序 | pending flush 是本地保存机制，不是新增的 snapshot 字段，也不是云端同步 |
| 后端业务确认/发布 | 店主明确确认前，Agent 后端不得写门店、商品等业务库，也不得发布；未来 v2 仍须保持该门槛 | 不能因为本地已有草稿快照就视为业务资料已生效 |

其他不变量：

- 未确认草稿驱动预览时，不提前修改 confirmed `store/build/visual`，不改变导出、发布或确认门槛。
- 确认仍只把 `storeName/category` 按既有规则晋升到 `store`；营业时间、履约和菜品继续保留在 `agentDraft`。
- 重新打开已确认草稿并编辑时，预览展示最新草稿，confirmed `store` 在下一次确认前保持不变。
- `activeRequestId` 是 transient，只存在内存，不进入 `project.json`；旧快照/草稿沿用既有恢复与校验，不清除、不覆盖用户资产。
- 本轮没有修改 `src/domain/projectSnapshot.mjs`，没有迁移或提升 snapshot schema。

## 7. 性能目标与测量缺口

本地 React commit 到浏览器 paint 的目标为 **P95 ≤ 150ms**。

截至任务 14 最终独立复验，仍**未按该口径实测**，所以当前状态只能写“目标，未实测”。没有记录 commit 起点、paint 终点、样本、设备/系统与浏览器环境，也没有 Performance trace。领域函数、Node 测试或 DOM 可见性检查耗时不等于 commit→paint，不能用来宣称性能达标。

后续测量至少应固定草稿规模与候选数量，记录 React commit 时间、浏览器实际 paint 时间、样本数、P95、硬件/操作系统/浏览器版本，并区分模型网络耗时。

## 8. v1 / v2 边界

| 项目 | 当前 `agent-turn.v1` | 后续 `agent-turn.v2` |
| --- | --- | --- |
| 状态 | wire contract 保持冻结，未伪升版 | 仅写入后端待实现建议，未实现 |
| 草稿字段 | 店名、品类、营业时间、履约、菜品等既有 ContractDraft | 如需展示修改，新增严格白名单 `presentationPatch` |
| 预览更新 | 完整响应接受后的本地 React 重投影 | 可复用 ViewModel 适配边界，但当前没有 v2 transport/adapter |
| 候选 ID | 使用既有本地候选 ID | 建议由服务端生成并校验稳定、不可复用的候选 ID |
| 并发与过期 | 前端进程内 requestId 防止晚响应改写 | 建议增加服务端 `baseRevision/turnId` 乐观并发与确认规则 |
| 写库/发布 | 明确确认前不写业务库、不发布；本地快照独立存在 | 仍必须显式确认、事务校验；确认不等于发布 |

详细 v2 建议见 `docs/后端待实现接口清单.md` 第 19 节。建议不是可用接口，前端不得提前调用或宣称已支持。
