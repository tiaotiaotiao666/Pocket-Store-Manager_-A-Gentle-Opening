### 附带修掉的两个真实故障

1. **「预览能打开、验证说工具缺失」**：`wechat-devtools-run.cjs` 原本只认 4 个候选路径，本机开发者工具装在 `E:\微信web开发者工具\cli.bat`（预览侧本来就能找到）。现在两条链路共用同一解析，验证侧也能命中。
2. **新包就绪判定绑死字段**：原逻辑用「首页 data 是否存在 `tablesLoading` 字段」判断模拟器是否加载到本轮新包，不含该字段的工程（例如旧导出）恒为 BLOCKED。现在改为「工程 `app.json` 首个页面能被 `reLaunch` 打开且 data 非空」，并把观测写进证据 `bundle.observation`。
3. **登录态判定只看 stdout**：`cli islogin` 的 `{"login":true}` 可能落在 stderr（IDE server 未启动时），现在两个流都看，拿不到就 BLOCKED，不猜。

## 2. 关键设计（供后续阶段复用）

~~~text
页面/交互证据
  → scripts/wechat-devtools-run.cjs          写 report.status = computeVerificationStatus(report).status
  → desktop/frontend-reconstruct/verify-runtime.cjs
        再算一次 verdict；report 自称 PASS 而 verdict 不是 PASS → 降级 + RUNTIME_INCONSISTENT
  → desktop/frontend-reconstruct-ipc.cjs      原样回传 status/verdict 计数，不二次解释
~~~

判定规则（唯一实现 `verification-status.cjs`）：

- 任一页面不是 PASS → **FAIL**；
- 任一交互 FAIL → **FAIL**（参考项 FAIL 也算，诚实性优先）；
- 有阻断原因，或任一**关键**交互不是 PASS（BLOCKED / NOT_RUN / 未知）→ **BLOCKED**；
- 没有页面也没有交互证据 → **NOT_RUN**；
- 其余 → **PASS**；参考项的非 PASS 进 `verdict.degraded`，如实展示但不定级。

关键/参考分级写在 `scripts/wechat-devtools-run.cjs#ADVISORY_INTERACTIONS`：加购、首页选桌→菜单、菜单选桌、结算提交下单是关键项；组件锚点补验、处理器直调的分类切换/购物车展开、桌号数据源、演示模拟支付是参考项。**没标 `critical` 的交互按关键项对待**，外部/旧证据不会被静默降级。

## 4. 真实证据

证据文件在 `docs/evidence/p0/`。

### 4.1 仓库链路（`node scripts/wechat-devtools-run.cjs`）

`repo-run.json`：真实微信开发者工具 CLI，无模拟：

~~~text
CLI：E:\微信web开发者工具\cli.bat
[PASS] login · exit=0 · 347ms
[PASS] compile · cli open --project（真实编译） · exit=0 · 8.2s
[PASS] automation · cli auto --auto-port · exit=0 · 23.0s
[PASS] 首页 /pages/home/index → pages-home-index.png
[PASS] 菜单 /pages/menu/index → pages-menu-index.png
[FAIL] 菜品详情 /pages/product-detail/index
[FAIL] 结算/下单入口 /pages/checkout/index
判定：页面 2/4 通过 · 关键交互 0/4 通过 · 页面未通过：菜品详情（FAIL）
结论：FAIL（exit 1）
~~~

该工程（`generated-projects/松月食堂`）是旧导出，缺 `onModeChange` 等处理器，所以关键交互 0/4；报告如实给 FAIL 并逐条列出原因——**这正是 P0 要的「交互失败不能被算成通过」**。

### 4.2 打包版（`release/win-unpacked/智能开店.exe`）

`packaged-run.json`：用打包后的 exe 以 Node 模式执行包内固定脚本，同样跑完整链路，产出真实截图 `packaged-home.png`、`packaged-menu.png`（19.5 KB / 22.2 KB，真实模拟器画面），结论同为 FAIL。

### 4.3 安装版（NSIS 静默安装）

~~~powershell
release\智能开店 Setup 0.2.0.exe /S /D=<安装目录>
~~~

- 安装目录 `resources/app/` 内断言：`scripts/wechat-devtools-run.cjs`、`node_modules/miniprogram-automator`（及其 `jimp/ws/debug/...` 依赖）、`desktop/devtools-cli.cjs`、`desktop/frontend-reconstruct/verification-status.cjs` 全部存在；`scripts/generate-mini-program.cjs` 不存在。
- 安装版 exe 以 `ELECTRON_RUN_AS_NODE=1` 执行包内固定脚本，返回结构化结论并写证据（`installed-run-environment-blocked.json`）。
- **环境阻塞（如实记录）**：本会话的进程写权限限制使安装版 exe 派生的开发者工具 CLI 无法写自己的 `%LOCALAPPDATA%\微信开发者工具\User Data\...\.cli`，登录步骤报 `EPERM`，因此安装版在本会话里止于 `BLOCKED`。同一脚本从仓库 `node` 运行时该文件可写，链路可跑通（4.1/4.2）。这是会话沙箱限制，不是安装包缺陷；在正常桌面上需按 4.3 的步骤复测一次。
