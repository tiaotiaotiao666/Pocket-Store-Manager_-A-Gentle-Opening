## 1.3 能力勾选与导出的如实披露（2026-11-09）

背景：`planFromSession.mjs` 的 `Plan.features` 只来自 Recipe，用户勾选不参与导出，但预览徽章按勾选展示，容易让人以为"勾了才导出、没勾就不导出"。

- 新增 `src/domain/capabilities.mjs` 作为 9 个 Base 内置能力的唯一来源（`BASE_CAPABILITY_IDS` / `isBaseCapability`）；`planFromSession.mjs`、`preflightRules.mjs` 删除各自重复的 Set。
- `preflightRules.mjs` 新增 `W-BASE-FEATURE-UNCHECKED`：勾选过能力时，对未勾选的 Base 可选能力（堂食桌号/自取外带/商家接单/商品估清/门店资料）提示"不会从导出工程移除，勾选只影响模板推荐"；一个都不勾时不提示，避免首屏噪音。
- `previewViewModel.mjs` 的 `capabilities` 每项增加 `exported`（仅 Base 内置为 true）；`PreviewTabs.jsx` 的"我的"页改为"能力与导出状态"，显示 `n/m 项随模板导出`，未导出项追加"· 未导出"并降透明度。
- 不反转已钉住的设计：运行时开关仍以门店资料 `storeProfile.fulfillment` 为准，不由 features 反推（`planFromSession.mjs` 的 fulfillment 逻辑未改）。
- 未做：真正按勾选裁剪页面/组件（M3 级，需要 Base/Composer 改造）；FrontendPack 也无法按能力开关 WXML。
- 真实视觉链路实证（同日）：`POST /api/v1/agent/turn` 带 `kind:'menu'` 截图（`docs/evidence/m7/wechat/order-poster-home.png`，81111B）→ HTTP 200、`model=deepseek-flash`、`vision.analyzed=true/degraded=false`、耗时 5.3s；模型识别出店名并主动说明"不是完整菜单照"，只落 1 道菜。说明多模态可用，但入参只有 menu/store，无法表达"这是参考页面截图"。
