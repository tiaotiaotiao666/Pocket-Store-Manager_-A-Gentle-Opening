# P5 演示脚本（3–5 分钟）

> 目标：讲清「普通开店主线」+「参考截图生成候选模板」这个创新点。
> 全程在本机桌面客户端里点，不切终端、不讲代码。所有数字都是实测值。

## 0. 开场（20 秒）

「这是轻启：一个把『我想开个小程序店』变成可交付小程序工程的桌面工具。我不用写代码，只用说话。产出是一个能被微信开发者工具直接打开的本地工程。」

## 1. 一句话开店（60 秒）

1. 点「我的项目」→「新建项目」→ 命名 `柑橘小馆演示店` → 命名并开始。
2. 功能选择页：扫码点餐 / 商品与菜单 / 购物车结算 / 订单进度已是必选；口头加一句「再加个会员积分」也可以，本次直接点「加入定制能力」。
3. 候选骨架出来 3 套：**街巷食集 / 一杯日常 / 主厨推荐**。
   - 点「一杯日常」→ 右侧手机预览实时换骨架（这次实测切换成功，`当前使用` 显示新骨架）。
   - 点预览底部的「菜单」标签，能看到真实菜单页。
   - 讲解词：「这一步是本地确定性组装，不是让模型瞎编页面，所以每次选出来的结构都可复现。」

## 2. AI 填门店资料（70 秒）

输入一句话：

```
店名是柑橘小馆，社区家常菜，10:00-21:00，堂食和自取，招牌牛肉饭 28 元、柠香鸡腿饭 26 元、时令小食拼盘 16 元。
```

- 界面显示「本轮共 N 次工具调用」+ 读取/更新门店资料/校验信息三步都打勾，草稿到 **5/5 类资料齐全**：店名、品类、营业时间、取餐方式、3 道菜。
- 再补一句：`时令小食拼盘改成 18 元，再加一道桂花酸梅汤 12 元。` → 草稿里出现新菜并改价，说明它是**可继续修改**的会话，不是一次性表单。
- 讲解词：「模型只负责抽取和补全，落草稿要过白名单工具和校验；不合规的字段改不动库。」

## 3. 参考截图 → 候选模板（创新点，60 秒）

1. 附加材料区「上传截图」，选一张别人小程序的首页截图（实测用 `03-templates.png`）。
2. 点「开始识别」→ 界面进入「正在识别截图」。
3. **如实说明**：本次演示机上游视觉模型返回 502，界面提示「图片识别服务当前不可用（上游视觉模型返回 502），这次没有识别结果，也没有生成候选模板」——它没有编一个假候选糊过去。点「放弃这条参考」即可回到干净状态。
4. 讲解词：「识别成功时会给出 2–3 个候选骨架让你确认或放弃；这一步的设计原则是只借鉴布局与组件组合，不复制对方源码、文案和品牌素材。」

## 4. 视觉与素材（40 秒）

- 海报素材页现在是真实 AI 生图：提示词已按店名/品类/风格/菜品拼好，可当场改一句再点「生成海报」，约 30 秒后出现真实图片。
- 生成前界面明确写着「文字需求会发送到第三方生图服务（模型 gpt-image-2.6）」，并给出「生成海报 / 上传本地图片 / 暂时跳过」三条路——跳过不阻断生成。
- 讲解词：「这里默认一次只生成 1 张，是为了把调用成本控住；选用的图会缩到 1024 边、2 MB 以内再入库，重开项目还能看到，导出时会作为首页主图写进工程。」
- 备选（外部服务不可用时）：点「上传本地图片」用一张自有 PNG 顶替，或「暂时跳过」，界面不会假装生成成功。

## 5. 导出（40 秒）

1. 导出页先做体检：出现 2 条提示（touristappid、仅写本地目录），逐条「我已了解」。
2. 展示 `Plan 摘要 sha256:…`——导出的是一份被摘要锁定的计划。
3. 点「选择导出位置」会弹系统目录对话框（说明这是唯一需要人手的一步）。
4. 口头给出等价命令行导出结果：「同一套 Composer，命令行跑出来 138 个文件，`output-lock.json` 摘要 sha256:4ee1eab7…，再写真实 AppID 后 `verified: true`。」

## 6. 收尾（20 秒）

「关掉客户端再打开，项目还在，回到上次的进度继续改；这就是本机工程化的意义：可中断、可恢复、可复现。」

## 备用问答

- **用了什么模型？** DeepSeek（`deepseek-*`），真实 HTTP 调用，`meta.provider=deepseek`、`mock=false`。
- **失败会怎样？** 上游异常时界面给明确错误码文案，草稿与项目不被破坏；模板匹配会回落到本地规则，界面标注「本地规则（模型不可用）」。
- **能直接上线吗？** 不能。导出只是本地工程；真机预览与体验版发布需要你自己的 AppID 与账号，我们不代做也不宣称做过。

## F1 增补：最终验收版演示（2026-11-19）

启动：

```powershell
# 后端（MySQL 5.7.26 / 3306 起来后）
cd server; npx prisma migrate deploy; npm run build; node dist/main.js

# 前端 + Electron
cd ..
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
$env:SMARTSTORE_EXPORT_DIR = "$PWD\node_modules\.cache\f1-exports"   # 本机工作区默认目录受看守，rename 必 EPERM
npm run agent:app
```

应用内「设置与自检」需确认：后端接口地址 `http://127.0.0.1:3000/api/v1`、模型通道「后端可用」、`readyz 200 / database=ok`。

演示顺序（每步都有对应截图，见 `evidence/f1-shots/`）：

1. 一句话建店 → 两段午休营业时间、堂食+自取、1 道菜 22 元。
2. 「营业时间改成 22:00 到次日 02:00，只留这一段」→ 表单变 `22:00–次日 02:00`。
3. 模板页：两套真实独立结构；点卡只预览（徽标不动），「就用这套」才切换。
4. 「主色换成暖橙，首页顶部主图矮一点，按钮文案改成『马上点餐』」→ 原话就近可见、2 项 before→after、按钮文案如实说没改；「撤销这次修改」回到上一版。
5. 海报素材：可以真实生成或上传，也可以跳过；跳过时不影响后面的导出。
6. 导出前体检：摘要与资料一致 →「可以导出」，只有告知型说明；导出产出 142 个文件。
7. 同名目录再导出不被覆盖；AppID 写入后产物摘要变化（`project.config.json` 更新 + `appid-postprocess.json`）。
8. 交付向导 6 步：明确「不自动上传/不发布」，并解释「真实渲染截图回传 ≠ 应用内实时渲染」。

演示边界（必须口头说明，不可演示）：微信开发者工具未安装 → 真实编译与运行、真机预览、体验版发布、真实支付均为 **NOT_RUN/BLOCKED**；参考截图识别链路本轮未执行（原生文件对话框无法自动驱动）。
