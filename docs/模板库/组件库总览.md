## 2. 组件分类

### 2.1 页面骨架与状态（shell，5）

| 组件 | 用途 | 关键 props | 事件 | 出现页面 |
| --- | --- | --- | --- | --- |
| `store-header` | 门店身份头，桌号/营业时间/地址/履约方式 | `storeName`（必填）、`tableName`、`businessHours`、`mode`、`address`、`compact` | 无 | home、menu |
| `fulfillment-switch` | 堂食/自取切换 | `value`、`dineInEnabled`、`takeawayEnabled`、`tableName`、`tableRequired` | `change` | home、menu |
| `state-view` | 加载/错误/空态壳 | `state`、`title`、`description`、`actionText` | `retry` | 全部 8 页 |
| `error-banner` | 内容流错误条 | `message`、`action`、`requestId` | `retry`、`close` | 全部 8 页 |
| `loading-block` | 列表骨架屏 | `rows`、`text` | 无 | menu、orders、merchant-orders |

## 4. 布局卡：暖橙首页与菜单

`warm-home-menu@1.0.0` 只覆盖 `home`、`menu` 两页视图：

- 首页区块顺序：加载态 → 首屏主视觉 → 品牌标题 → 错误态 → 提示条 → 营销插槽 → 用餐方式 → 开始点餐 → 待付款提醒 → 进行中订单 → 店主入口 → 演示说明。
- 菜单页区块顺序：加载态 → 紧凑头部 → 错误态 → 标题区 → 主视觉插槽 → 侧栏插槽 → 分类导航 → 菜品列表 → 购物车条 → 购物车面板 → 菜品详情弹层。

布局卡中的 `blocks[].components` 只记录直接归属组件；嵌套区块归属最内层。

## 6. 已知缺口

| 缺口 | 状态 | 下一步 |
| --- | --- | --- |
| `slots.json` 未列 `menu-hero` | warning；以 Base Manifest 为准 | Base 版本升级时补齐并重冻结 |
| 23 个区块只覆盖 FrontendPack 的 home/menu | 已知边界 | 需要时增加 Base 8 页区块投影 |
| 大多数自有视觉区块仍是 `promote-to-ui-block`（8/23；另有 `base-component-use` 8、`slot-only` 4、`direct-wxml` 3） | 已知边界 | 按 `uiBlockBlueprint` 立项提升，不在模板生成中生成 JS |
| `Plan.components` 不复制 Base 同名组件 | Composer 既有偏差 | 需要组件替换能力时先改 Composer 并补测试 |
