# 产品范围与信任边界

## 1. 用户流程

1. 店主通过会话式工作台填写或自然语言描述门店资料，并确认结构化草稿。
2. 勾选必选和可选经营功能。
3. 查看功能匹配度，选择已验证模板；未来可由 Agent 根据注册表生成受约束的组合方案。
4. 选择风格，预览并生成页面图标或视觉资源。
5. 使用桌面效果预览，导出独立原生小程序工程，再用微信开发者工具检查真实运行效果。

## 2. 生成器与门店小程序的关系

生成器是店主本机使用的 Windows 应用，不是所有门店共用的顾客小程序。导出目录是一份可单独导入微信开发者工具的源代码工程。

每家门店必须使用自己的微信小程序账号、主体和 AppID，自行完成认证、合法域名配置、上传、审核和发布。生成器不代办这些平台操作，也不将门店挂靠到生成器运营主体。

## 3. 当前 AI 能力边界

当前已实现两类模型相关能力：

- `generation`：OpenAI 兼容图像生成/编辑和视觉风格推荐适配；不代表华为云已经接通。
- `agent/turn`：DeepSeek 提取开店资料并生成回复，NestJS 白名单合并和独立校验；不写业务数据库，不生成代码。

当前没有 Skill、工具调用、多 Agent、自主规划、开放式代码生成、自动发布或 Agent 会话持久化。桌面端默认仍可使用明确标识的本地 Mock。

## 4. 未来模板组合的 AI 边界

模板库规划允许 Agent 做“需求理解和组合规划”，但不允许它自由生成业务源码：

- 只能选择注册表内已登记、版本兼容且验证通过的 Base、UI Block、Feature Pack 和 Recipe。
- 只输出 CompositionPlan 候选，由独立校验和确定性 Composer 决定最终工程。
- 未登记能力必须标为待开发，不能通过模型即兴写代码补齐。
- 只有 `online-ready` 资产可以发布为在线能力；`preview-only` 不得冒充真实后端功能。
- 新组合首先只是候选 Recipe，通过编译、测试和发布审核后才能进入正式模板库。

详细方案见 `docs/模板库与组合生成规划.md`。这一规划不改变“禁止开放式 AI 代码生成”的红线。

## 5. 数据、图片与密钥

- 用户必须主动选择门店图片，并在云端发送前确认发送范围。
- 客户端不保存模型 API 密钥；密钥只在服务端环境或密钥管理系统。
- DeepSeek Key 不得作为客户端 Token，不得进入日志、错误体、导出工程或仓库。
- 门店业务数据、CompositionPlan 和生成资产分离；导出工程只包含公开配置。
- 金额以整数分传输和存储，订单金额由服务端计算。

## 6. 当前版本不包含

- 真实微信支付、退款、对账和外送/配送调度。
- 公开店主自助注册、客户端授予角色、自动上传审核发布。
- 已联通的在线点餐闭环：B1/B2 仍是后续执行范围。
- 已实现的组件注册表、CompositionPlan、Composer 和云端模板库。
- 云端项目/会话持久化和真实部署任务。

在线点餐、模板库和云端能力均已纳入分阶段路线，不代表永久取消。统一顺序见 `docs/后端实现方案与套餐.md`。
