## 4. B1 范围与实现顺序

严格按下列顺序，每一步写完先自测，再进入下一模块。

### 4.1 `common`（先做，后续模块都依赖）

建议新增：

```text
server/src/common/
  filters/all-exceptions.filter.ts      统一错误体 {code,message,requestId,details?}
  interceptors/request-id.interceptor.ts 生成 req_ 前缀 requestId，回写响应头
  guards/auth.guard.ts                  Bearer → session → user
  guards/store-member.guard.ts          从数据库读取 OWNER/STAFF，不信任客户端
  decorators/current-user.decorator.ts
  utils/id.ts                           ULID（建议安装 `ulid`）
  utils/errors.ts                       业务错误构造器
```

要点：

- 错误体严格按 `docs/api.md` §1；禁止返回堆栈、SQL、OpenID、密钥。
- `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`。
- requestId 同时写入响应头 `X-Request-Id`。
- 认证 Guard 从 `sessions` 表按 SHA-256(token) 查询，过期或不存在 → `401 AUTH_INVALID`。
- 会员 Guard 查 `store_members`；跨店 → `403 FORBIDDEN`；资源不存在 → `404`。

### 4.2 `auth`

端点：

- `POST /auth/wechat/login`
- `GET /auth/me`

实现要点：

- 真实流程：`code` → 微信 `jscode2session`（fetch），只接受服务端换取的 OpenID。
- 演示流程：`NODE_ENV !== production && ALLOW_DEMO_LOGIN=true` 时接受 `demoOpenId`；否则 `403 DEMO_LOGIN_DISABLED`。
- 首次登录创建 `users`；**不创建成员、不授予角色**。
- 会话：`crypto.randomBytes(32)` 生成 opaque token，DB 存 SHA-256，`expiresAt = now + SESSION_TTL_SECONDS`（默认 7 天）。
- 返回 `memberships` 只读数据库。

### 4.3 `stores` / `catalog`

- `GET /stores/:storeId`（公开）：返回名称、地址、电话、营业时间、`fulfillment`、`theme`。
- `GET /stores/:storeId/catalog`（公开）：
  - 只返回 `available=true`；
  - 先读 Redis `catalog:{storeId}`，未命中查库并写缓存（建议 TTL 300s）；
  - 返回 `version`（`stores.catalogVersion`）、`updatedAt`、分类与商品；
  - 金额使用 `priceCents` 整数。

### 4.4 `orders`

端点：

- `POST /orders`
- `POST /orders/:id/demo-payment`
- `POST /orders/:id/cancel`（§9 增补）
- `GET /orders`
- `GET /orders/:id`

实现要点：

- 创建订单必须带 `Idempotency-Key`（8–128 可见 ASCII）。
- 下单事务内：
  1. 校验门店、履约方式、堂食桌号归属；
  2. 只接受 `available=true` 商品；
  3. 合并重复 `productId`，数量 1–99；
  4. 服务端按数据库单价计价，忽略客户端价格；
  5. 写 `orders`、`order_items` 快照、首条 `order_status_logs`、`idempotency_keys`。
- 幂等：`(userId, storeId, key)` 唯一；请求指纹一致返回原订单（200），不一致 `409 IDEMPOTENCY_CONFLICT`；保留 24 小时。
- Demo 支付：本人、`PENDING_PAYMENT`；成功后 `PENDING_ACCEPT` + `DEMO_PAID`，写日志；重复调用幂等返回；`ALLOW_DEMO_PAYMENT=false` 或生产 → `403 DEMO_PAYMENT_DISABLED`。
- 取消：本人、`PENDING_PAYMENT` → `CANCELLED`，写 `CUSTOMER` 日志；重复取消幂等；已付款后取消 → `409 INVALID_STATUS_TRANSITION`。
- 列表：`storeId` 必填、`status` 可逗号分隔、`active`、分页。
- 详情：本人或门店成员可读；否则 `404 ORDER_NOT_FOUND`；含按时间升序的 `statusHistory`。

### 4.5 `merchant`

端点：

- `GET /merchant/stores/:storeId/orders`
- `PATCH /merchant/orders/:id/status`
- `PATCH /merchant/products/:id/availability`
- `GET /merchant/stores/:storeId/products`（§9 增补，含下架商品）

实现要点：

- 全部要求 Token 用户在该店为 `OWNER`/`STAFF`。
- 订单列表默认 `PENDING_PAYMENT,PENDING_ACCEPT`，`createdAt` 升序。
- 状态推进：
  - 先校验转换矩阵；
  - `expectedStatus` 可选，不一致 → `409 STATUS_CONFLICT`；
  - `UPDATE orders ... WHERE id=? AND status=?`，受影响 0 行 → `409 STATUS_CONFLICT`；
  - 同一事务写日志；
  - 店主处理 `PENDING_PAYMENT` → `409 MERCHANT_CANNOT_HANDLE_UNPAID`。
- 商品上下架：事务内 `catalogVersion + 1`，提交后删除 Redis `catalog:{storeId}`。

### 4.6 状态机

建议抽出纯函数 `server/src/orders/order-state.ts`，便于单测：

```ts
type OrderStatus = 'PENDING_PAYMENT' | 'PENDING_ACCEPT' | 'PREPARING' | 'READY' | 'COMPLETED' | 'CANCELLED';
canCustomerPay(from): boolean
canCustomerCancel(from): boolean
nextMerchantStatus(from): OrderStatus | null
canMerchantTransition(from, to): boolean
```

转换矩阵只以 `docs/order-state.md` §2 为准。

## 7. 已知坑（务必避开）

1. **MySQL 中文路径**：基于 `E:\智能开店app` 会导致 basedir 被截断成 `E:\`。运行时必须放 `E:\smartstore-tools\mysql`（纯 ASCII）。
2. **WSL 网络**：必须保持 `C:\Users\leiji\.wslconfig` 的 `networkingMode=mirrored`；WSL VM 空闲会挂起导致 6379 间歇 ECONNREFUSED，需常驻 `tail -f /dev/null`。
3. **ioredis 重试**：client 首次连接失败后不可复用；`CacheService` 已改为每次新建 client（5 次 × 1s），不要再复用。
4. **Prisma 版本**：固定 6.x；`npx prisma@latest` 会装 7，破坏现有 client 生成方式。
5. **`@nestjs/testing` 版本**：必须 `^11`，装 12 会与 `@nestjs/common@11` 冲突。
6. **tsconfig include**：`server/tsconfig.json` 已限制为 `src/**/*.ts`；否则 `prisma/seed.ts` 会把输出带到 `dist/src/main.js`。
7. **CORS**：已允许 `PATCH` 与 `Idempotency-Key`；新增方法/头时同步改 `main.ts`。
8. **`.env` 已被 `.gitignore` 忽略**；不要把真实密钥写进 `.env.example`。
9. **Node 24**：当前实测可用；Prisma 引擎正常。
10. **npm audit**：当前 8 个漏洞（5 high），B1 收尾时评估，不要盲目 `audit fix --force`。
