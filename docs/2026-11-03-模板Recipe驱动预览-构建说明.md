# 模板 Recipe 驱动预览 —— 构建说明

> 日期：2026-11-03
> 范围：桌面端模板选择页预览 ↔ 导出小程序工程的一致性打通
> 面向读者：后续接手本仓库的 AI 或其他工程师
> 本文所有结论均来自本轮真实命令输出，未复跑的门禁在「7. 未完成与边界」中单列。

---

## 1. 本轮要解决的问题

用户在模板选择页看到的三张模板卡片，与导出后在微信开发者工具里跑起来的小程序**外观完全不一致**。

本轮不是"再写一遍预览 UI"，而是把预览层接上**已经存在但一直没被消费**的 `CompositionPlan` 机制。

---

## 2. 根因（依据代码，不是推测）

仓库里"模板"相关实现分成三层，此前互不相通：

| 层 | 代码 | 事实 |
| --- | --- | --- |
| 模板页预览 | `src/composition/previewViewModel.mjs` + `src/components/preview/*` | React 手写复刻，从未读取 `plan.features` |
| 导出生成 | `templates/base/ordering-base/1.0.0/src` + `scripts/composer/` | 7 页面 / 14 组件，Composer 支持 slot 注入 |
| 真实小程序 | `miniprogram/` | 与 base 模板镜像（14 个组件逐字节一致） |

断点集中在两处：

```js
// 修复前 src/composition/planFromSession.mjs
const TEMPLATE_TO_RECIPE = {
  'warm-bistro': 'order-classic',
  'modern-coffee': 'order-classic',      // 三个候选 → 同一个 Recipe
  'signature-kitchen': 'order-classic',
};
```

```js
// 同文件，Plan 里 features 恒为空
features: [],
```

因此导出侧虽然有 `poster-carousel` Feature Pack、有 `slots.v1` 锚点、有 `preview/*.json` 示例数据，但**没有任何调用方**把配方接进去。

## 3. 本轮改动（逐文件）

### 3.1 新增 `src/domain/recipeCatalog.mjs`

- 运行时可用的 Recipe 投影：`RECIPES`、`TEMPLATE_TO_RECIPE`、`resolveRecipe()`、`describeRecipe()`。
- `features` 结构逐字对齐 `templates/recipes/<id>/1.0.0/plan.json`。
- 所有查找走 `Object.prototype.hasOwnProperty`（`__proto__` / `constructor` 不会穿透到 `Object.prototype`）。
- `resolveRecipe()` 返回**深拷贝**，调用方改写不会污染冻结常量。

不直接 `import` JSON 的原因：同一模块要同时被 Vite（渲染层）、Node ESM（测试）、CommonJS（Composer）消费，JSON import 断言的写法在三处不一致。两处一致性由机械门禁保证（见 3.7）。

### 3.2 修改 `src/composition/planFromSession.mjs`

- 移除本地 `TEMPLATE_TO_RECIPE`，改为 `resolveRecipe()`。
- `plan.features` 从恒空改为携带选中 Recipe 的真实配方。
- `plan.planVersion` 与 `plan.registryVersion` 改为从 `recipeCatalog` 取，不再硬编码。
- 返回值新增 `recipeDisplayName`。

映射结果（**这是本轮的真实状态，不是设计目标**）：

| 候选模板 | Recipe | 依据 |
| --- | --- | --- |
| `warm-bistro` 街巷食集 | `order-classic` | 菜单优先，与基线吻合 |
| `modern-coffee` 一杯日常 | `order-classic` | **与街巷食集共用配方**，差异只来自主题 Token 与候选 `layout` |
| `signature-kitchen` 主厨推荐 | `order-poster` | 语义最吻合「大幅主图 / 招牌展示」 |

### 3.3 修改 `src/composition/previewViewModel.mjs`

- 新增 `recipe` 字段：`{ id, displayName, version }`，由 `plan.planId` 反查。
- 新增 `blocks` 字段：把 `plan.features[].slots[]` 投影成预览块。
- 新增 `PREVIEW_BLOCK_TYPES` 白名单，只登记“Composer 能注入 + React 能渲染”的块。
- poster props 按 Feature Pack manifest 的 `interface.props` 清洗：
  - `items` 先过滤（无标题丢弃）再截断到 6 张；
  - `tone` 只允许 `warm|green|ink`，否则回落 `warm`；
  - `title` ≤24 字、`subtitle` ≤40 字；
  - `interval` 钳制到 3000–8000ms，非数值回落 4000；
  - `autoplay` / `showIndicator` 只接受布尔 `true`；
  - **刻意不投影 `image`**：Plan 禁止外部 URL，预览不应渲染未经校验的资源地址。
- `buildSessionPreviewViewModels()` 改为**每个候选按自己的模板解析 Plan**（此前三个候选共用一个 Plan，等于三张卡片永远是同一套结构）。门店资料仍全 session 共享，只有 Recipe 跟随候选。

### 3.4 新增 `src/components/preview/PosterCarouselBlock.jsx`

- 视觉与行为对齐 `templates/features/poster-carousel/1.0.0/src/components/poster-carousel`：
  - 三档语气渐变与组件 `index.wxss` 同源；
  - `items` 为空时渲染 `POSTER` 占位，对应 wxml 的 `wx:else`；
  - 指示点、自动播放、点击切下一张。
- 只依赖 `react`（结构门禁已加入白名单）。
- 不渲染 `image`，与 manifest 的 `knownLimits`「演示海报使用主题渐变色块」一致。

### 3.5 修改 `src/components/preview/MiniProgramPreview.jsx` / `PreviewTabs.jsx`

- compact 与 full 都先查 `home-hero` 块：
  - 有块 → 渲染 `PosterCarouselBlock`；
  - 无块 → 回落到原有 `HeroBanner`（对应 `fragments/home-hero.fallback.wxml`）。
- 两个组件各自保留本地 `findHeroBlock()`，避免 `PreviewTabs → MiniProgramPreview → PreviewTabs` 循环依赖。

### 3.6 修改 `src/components/flow/TemplateGallery.jsx`

- 卡片与详情区新增配方名标签（`.template-recipe`），让用户直接看到“选的是哪套配方”，而不是只看到换了配色。

### 3.7 修改 `scripts/composer/emit.cjs`（**修复既有阻断缺陷**）

`replaceSlotAnchors()` 此前把组件属性写在标签**外面**：

```wxml
<!-- 修复前：属性是裸文本，微信 WXML 会解析失败 -->
<poster-carousel>
  autoplay="{{slotProps.homeHero[0].props.autoplay}}"
  ...
</poster-carousel>
```

现改为自闭合标签，属性位于标签内部：

```wxml
<poster-carousel
  autoplay="{{slotProps.homeHero[0].props.autoplay}}"
  interval="{{slotProps.homeHero[0].props.interval}}"
  items="{{slotProps.homeHero[0].props.items}}"
  show-indicator="{{slotProps.homeHero[0].props.showIndicator}}"
/>
```

该缺陷在打通 Plan → Composer 后才暴露；此前 `preview-registry.json` 为空、无任何 Recipe 真的分配插槽，所以从未触发。

### 3.8 样式

- `src/styles/preview.css`：新增 `.mini-poster*` 系列（full 高度 118px、compact 56px），三档渐变与组件 wxss 同源。
- `src/styles/flow.css`：新增 `.template-gallery .template-recipe`。

## 6. 新增契约（供后续扩展参考）

### 6.1 预览块白名单

```js
// src/composition/previewViewModel.mjs
const PREVIEW_BLOCK_TYPES = Object.freeze({
  'poster-carousel': Object.freeze({
    slotId: 'home-hero',
    maxItems: 6,
    tones: Object.freeze(['warm', 'green', 'ink']),
  }),
});
```

新增预览块必须同时满足两件事，否则不予登记：

1. Composer 能在同一 Recipe 下真的注入它（`emit.cjs` 的 slot 锚点链路）；
2. 有一个 React 组件按同一份 props 渲染。

**不允许**按 Feature ID 猜测结构——未登记 ID 一律静默忽略。

### 6.2 ViewModel 形状变化

```js
{
  schemaVersion: 'preview-view-model.v1',
  layout,                                   // 保留，降级为兜底提示
  recipe: { id, displayName, version },     // 新增
  blocks: [{ id, slotId, dataKey, props }], // 新增
  theme, store, hero, products, menuCountText, tabs, order, capabilities
}
```

## 7. 未完成与边界（必须如实交接）

### 7.1 只有两套真实配方，不是三套

`modern-coffee` 与 `warm-bistro` 共用 `order-classic`。用户在这两个模板之间切换时，导出工程的**结构与组件完全相同**，差异只有 `themeTokens` 与候选 `layout`。

要让三套真正不同，必须新增第三份 Recipe（例如 `order-compact`）并按 `docs/模板库与组合生成规划.md` 的流程重新冻结注册表。**本轮未做。**

### 7.2 预览仍是 React 复刻，不是 wxml 真渲染

本轮解决的是“结构信息从 Plan 来”，不是“渲染 wxml”。预览的 DOM 仍然由手写 React 组件产生。真机与预览的差异仍然存在（例如 swiper 的手势、`rpx` 换算、真机字体）。

规划文档 `docs/模板库与组合生成规划.md` §2 明确：**不用桌面 React 预览替代微信开发者工具验收**。本轮的验证口径同样遵守这条。

### 7.3 预览仍缺 5 个真实页面

预览只有首页 / 菜单 / 订单 / 我的四个 tab。真实小程序还有 `checkout`、`order-detail`、`merchant-orders` 三个页面，以及分类导航、购物车悬浮条、购物车面板、商品详情弹层、用餐方式切换、桌号选择这些组件。**本轮未补。**

### 7.5 发现的既有缺陷（本轮未修，建议登记 BUG）

`npm run composer:verify --root <任意导出工程>` 必然在 `security-scan` 失败：

```text
✗ security-scan：PATH_ESCAPE@generation-report.json:84 | PATH_ESCAPE@生成报告.md:7
```

原因：Composer 把输出目录的**绝对路径**写进了产物目录内的 `generation-report.json` 与 `生成报告.md`，而安全扫描把这两个文件当作产物扫描。

已核对：**经典配方工程同样命中**，与本轮改动无关，属既有缺陷。修复涉及“报告文件是否应落进产物目录 / 是否应从安全扫描范围排除”，需要单独决策，本轮未改。

桌面端实际导出只调用 `compose`，不调用 `verify`，因此不影响导出成功，但会让按文档执行校验的人看到失败。

## 9. 复现本轮验证的最短路径

```bash
# 1. 全量测试与构建
npm test && npm run build

# 2. 生成两份对照 Plan
node .resultverify/gen-plan.mjs .resultverify

# 3. 生成真实小程序工程（输出到系统临时目录，避免 Windows 目录 rename 权限问题）
node scripts/composer/cli.cjs --plan .resultverify/plan-signature-kitchen.json \
  --out "$TEMP/composer-check" --project-name songyue-poster --json
grep -n "poster-carousel" "$TEMP/composer-check/songyue-poster/pages/home/index.wxml"

# 4. 真实浏览器验证
npx vite --host 127.0.0.1 --port 5187 &
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new \
  --remote-debugging-port=9333 --user-data-dir=.resultverify/chrome-profile-poster \
  http://127.0.0.1:5187/ &
node .resultverify/cdp-poster-check.mjs
```

注意：Windows 上 `--out` 指向 `.resultverify/` 时会因目录 rename 权限报 `EPERM: operation not permitted`，改用系统临时目录即可（本轮已实测）。
