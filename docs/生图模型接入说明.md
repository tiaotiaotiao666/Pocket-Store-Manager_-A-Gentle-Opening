# 生图模型接入说明

> 状态：imagelfk 已于 2026-11-01 通过项目真实 HTTP 链路验证。当前服务商是第三方，不代表已接入华为云。

## 1. 什么时候调用

- 适合：根据页面名称生成餐饮图标、根据参考图生成同风格图标。
- 不适合：页面布局、按钮样式、文本生成、SVG 图标。普通 UI 图标优先使用 lucide/iconfont。
- 前端不得直连上游模型。统一调用本项目后端，密钥只存在服务端。

## 2. 配置

`server/.env`（已被 Git 忽略）：

```env
IMAGE_PROVIDER_NAME=imagelfk
IMAGE_API_BASE_URL=https://imagelfk.cc.cd/v1
IMAGE_API_KEY=<只在本机填写真实 SK>
IMAGE_MODEL_NAME=gpt-image-2
VISION_MODEL_NAME=
IMAGE_API_TIMEOUT_MS=90000
```

前端 `.env.local`（同样被 Git 忽略，不含密钥）：

```env
VITE_IMAGE_MODEL_ENDPOINT=http://127.0.0.1:3000/api/v1/generation
```

修改 Vite 环境变量后必须重启前端。未配置 `VITE_IMAGE_MODEL_ENDPOINT` 时，`src/services/imageService.js` 返回 `provider: local-demo` 的 SVG 占位图，不得称其为 AI 生成。

## 3. 项目接口

### 健康检查

```http
GET /api/v1/generation/health
```

`configured: true` 且 `imageModel: true` 只表示配置完整，不代表收费调用一定成功。当前 `VISION_MODEL_NAME` 为空时会回退到图像模型名，因此 `visionModel: true` 不能证明视觉分析可用。

### 生成图标

```http
POST /api/v1/generation/icons
Content-Type: application/json
```

无参考图请求：

```json
{
  "name": "招牌拿铁",
  "theme": "modern-coffee",
  "seed": 1
}
```

带参考图时增加 `referenceImages`，每项是 PNG/JPEG/WebP 的 data URL：

```json
{
  "name": "招牌拿铁",
  "theme": "modern-coffee",
  "seed": 2,
  "referenceImages": ["data:image/png;base64,<图片 base64>"]
}
```

可复制执行的 Git Bash 示例：

```bash
curl.exe -X POST "http://127.0.0.1:3000/api/v1/generation/icons" \
  -H "Content-Type: application/json" \
  -d '{"name":"招牌拿铁","theme":"modern-coffee","seed":1}'
```

成功响应（base64 已截断）：

```json
{
  "dataUrl": "data:image/png;base64,<完整 PNG base64>",
  "provider": "imagelfk",
  "disclaimer": "该图像由已配置的图像模型生成。"
}
```

前端直接调用：

```js
import { generateIcon } from '../services/imageService.js';

const result = await generateIcon({ name: '招牌拿铁', theme: 'modern-coffee', seed: 1 });
// result.dataUrl 可赋给 <img src>；result.provider 用于区分 imagelfk 与 local-demo。
```

## 4. 参数与当前限制

- `name`、`theme` 必填；`seed` 可选；一次返回一张图。
- 适配层向上游固定发送 `size=512x512`、`n=1`、`response_format=b64_json`。2026-11-01 实测服务接受请求，但两张返回 PNG 实际都是 **1254×1254**，调用方不要依赖输出恰好是 512×512。
- 服务层允许最多 5 张参考图，单张解码后不超过 5 MB；但当前 HTTP 默认请求体限制约为 100 KB，大 base64 请求会先返回 413。本次仅以 180 字节的小 PNG 验证编辑链路，未证明大参考图端到端可用。
- 当前适配层没有发送 `quality=low`，不得声称项目调用使用了低质量/低成本档位。
- 超时配置代码上限为 90 秒；实测两次成功调用分别约 36 秒和 33 秒。

## 5. 错误处理

| 状态/错误码 | 含义与处理 |
| --- | --- |
| `ICON_NAME_REQUIRED` | 补全非空 `name` |
| `THEME_REQUIRED` | 补全非空 `theme` |
| `MODEL_PROVIDER_NOT_CONFIGURED` | 检查服务端 Base URL、SK、模型名后重启 |
| `REFERENCE_LIMIT_EXCEEDED` | 参考图超过 5 张 |
| `REFERENCE_IMAGE_TOO_LARGE` | 单张参考图超过服务层限制 |
| `REFERENCE_IMAGE_INVALID` | 只使用合法 PNG/JPEG/WebP data URL |
| HTTP 413 | 请求体超过 HTTP 层限制；先缩小参考图，不要把 5 MB 当成当前可用保证 |
| `IMAGE_PROVIDER_FAILED` | 上游拒绝请求；保留脱敏错误，检查模型和参数 |
| `IMAGE_PROVIDER_UNAVAILABLE` | 网络或超时；稍后重试，不要循环批量调用 |
| `IMAGE_RESPONSE_INVALID` | 上游没有返回合适的 `data[0].b64_json` |

真实失败响应示例（大参考图触发）：

```json
{"statusCode":413,"message":"request entity too large"}
```

## 6. 本地复现

1. 按第 2 节配置 `server/.env`；准备项目要求的 MySQL，安装服务端依赖并执行 `npx prisma generate`。
2. 在 `server/` 执行 `npm run build && npm run start:prod`。
3. 请求 `http://127.0.0.1:3000/api/v1/generation/health`，确认 `configured` 和 `imageModel` 为 true。
4. 执行第 3 节 curl，保存 `dataUrl` 的 base64 部分并解码为 PNG；检查 `provider` 不是 `local-demo`。
5. 需要页面调用时配置前端 `.env.local` 并重启 `npm run dev`，沿用 `generateIcon`，无需改 UI。

本次真实探测记录和结果图片见 [`evidence/image-provider/probe.md`](evidence/image-provider/probe.md)。

## 7. 成本与安全红线

- 正常调试验证一次文生图、一次小参考图编辑即可，调通即停；失败排查先确认是否到达上游，不对本地 4xx 反复扣费。
- 项目响应不保留上游 `usage`，当前没有可核验的人民币单价；成本记录写真实耗时和调用次数，不编价格。
- SK 只能放 `server/.env` 或云端密钥管理，不得进入前端、小程序、导出工程、日志、文档或 Git。
- 不改变 `/api/v1/generation/*` 路径和响应字段，不让前端直连 imagelfk。
- imagelfk 的调用证据不能写成华为云接入证据；华为云必须另配 provider 并留下真实调用记录。
