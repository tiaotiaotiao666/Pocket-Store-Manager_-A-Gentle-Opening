## 3. 启动顺序

所有命令在仓库根目录执行。以下命令只用于后续人工启动，R3 未重跑验收。

### 3.1 一键启动（优先）

```powershell
npm run start:all -- -SkipMysql -Seed
```

- 已有 MySQL 监听 3306 时使用 `-SkipMysql`；否则去掉该参数，让脚本尝试启动本机 MySQL。
- 仅启动后端可加 `-ServerOnly`；3000 被旧后端占用且 readiness 不通过时用 `-RestartBackend`。
- 不要在共享电脑的 3306 上贸然执行 `npm stop`，它可能停止当前占用该端口的 MySQL。

### 3.2 分窗口启动（便于录屏排查）

```powershell
# 窗口 A：数据库已启动后
cd server
npx prisma migrate deploy
```


## 9. T0 全局缩放修复（2026-11-23）

### 9.1 根因

基线 `e03e287` 的 `desktop/main.cjs` **完全没有缩放代码、也没有自建菜单**，`Ctrl+- / Ctrl+= / Ctrl+0` 全部落到 Electron 默认菜单的 `zoomIn / zoomOut / resetZoom` 角色上：

- 这三个角色按 `zoomLevel`（1.2 的幂）步进，**没有上下限**，可以一直缩到 25%、10% 甚至更小，界面被压成中央窄条；
- Chromium 会把每个 host 的 zoomLevel 写进 `<userData>/Preferences` 的 `partition.per_host_zoom_levels`，于是重启后仍按极小值恢复，`Ctrl++` 又因拿不到 `'+'` 键而完全失效，形成“永久卡死”；
- 该状态没有任何钳制点，也没有恢复入口，属于全局缩放持久化/恢复链路故障，不是页面布局问题。

### 9.2 修复

新增 `desktop/window-zoom.cjs`，作为缩放的唯一实现；`desktop/main.cjs` 只做接线：

- 一律使用 `webContents.setZoomFactor`（不用 zoomLevel 角色），步进固定 0.1，范围钳制在 **50%–200%**，上下对称；
- `Ctrl+-` 缩小；`Ctrl+=`、`Ctrl+Shift+=`、数字小键盘 `Ctrl+Add` 放大；数字小键盘 `Ctrl+Subtract` 缩小；`Ctrl+0` 立即回到 100%；
- 快捷键由 `before-input-event` 处理并 `preventDefault`，只认 `keyDown + Ctrl + 无 Alt/Meta`，普通输入与 `Ctrl+C/V` 不受影响；
- 读取持久化值时逐项 `zoomLevel → factor` 换算并钳制，缺失/损坏/非数字/越界值一律落回安全范围；
- 持久化唯一事实源是 `<userData>/zoom-preference.json`（只存 `{factor}`）。曾试过直接写 Chromium 的 `Preferences.partition.per_host_zoom_levels`，实测**会被 Chromium 退出时重写覆盖**（写 100% 后重启又回到 120%），因此改为自己的文件，Chromium 那份只做尽力镜像，避免加载瞬间闪回旧值；
- 滚轮/手势缩放走 `sync()`：只把当前值拉回范围内，不叠加步进；
- 应用菜单改为「编辑 + 视图」：视图里是三档缩放 + 一个只读的「当前缩放：xx%」状态项；该状态项由代码按真实 zoomFactor 重建菜单得出，因此显示值不会与实际比例脱节。同时显式保留 `Ctrl+C/V`、重新加载、开发者工具、全屏，避免替换菜单带来的快捷键回退。

### 11.1 待确认卡片「前往确认」（Issue 6）

#### 11.1.1 状态一致性（同一轮补充，2026-11-24）

### 11.2 店名 20 字上限（Issue 7）

- 根因：输入框不限长，下游各层各写 48 字上限并在保存/生成/导出时静默截断，用户看不到「超了」。
- 修法：唯一规则源 `src/domain/storeName.mjs`（`STORE_NAME_MAX_LENGTH = 20`，按字素计数/截断，`STORE_NAME_LEGACY_MAX_LENGTH = 48` 仅用于老数据读入与导出体检）。输入层 `StoreNameField.jsx` 在输入/粘贴/拖拽/输入法提交时统一收敛，显示「当前字数/20」，到限给浅提示，粘贴超长提示「已按 20 字上限截断」。`AGENT_DRAFT_LIMITS.maxStoreName`、`appCapabilities` 的 `store.name.maxChars`、服务端快照 `capabilities.snapshot.json`、`agent-draft.validator.ts` 全部收敛到 20；服务端仍会拒绝超限提案（`APP_ASSISTANT_VALUE_INVALID`），不是只在 UI 拦。
- 不使用 `maxLength`：它按 UTF-16 截断会切坏 emoji/ZWJ 组合；输入法组合期间不截断，`compositionend` 后再收敛。
- 老数据：`projectSnapshot`/导出体检/Composer 仍用 48 兼容上限，历史店名超过 20 字打开与导出都不被改写；重新编辑时按 20 字规则收敛并显示最终名。
- 真实 Electron 验证：键入 21 字 → 落 20 字、计数 `20/20`、提示「已到 20 字上限」；粘贴 30 字 → 落 20 字、提示「已按 20 字上限截断」；粘贴 25 个 😀 → 20 个且无孤立代理；输入法组合中 21 字不打断、`compositionend` 后收敛为 20；保存后 `project.json` 的 `store.name` 与输入完全一致（9 字实存 9 字），重开项目输入框仍显示同名。证据：`issue7-paste-limit.png`。
