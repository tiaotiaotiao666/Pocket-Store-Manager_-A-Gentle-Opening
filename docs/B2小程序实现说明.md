## 1. 这轮交付了什么

`miniprogram/` 从「只有 `Page({});` 的骨架」变成了可对接 B1 后端的完整点餐小程序：

```text
miniprogram/
  app.{js,json,wxss}          启动、页面注册、全局设计 Token
  config/env.js               API 地址、演示身份、演示桌号、超时与开关
  domain/                     纯函数：金额、购物车、状态机、扫码、幂等、订单展示、错误文案
  services/                   唯一请求边界：platform、request-core、request、session、auth、store、order、merchant
  state/                      页面级共享状态：到店上下文 visit-store、购物车 cart-store
  components/                 13 个 UI Block，四件套齐全
  pages/                      7 个页面（新增 order-detail）
  styles/component.wxss       组件共享样式
```

覆盖的演示路径：

```text
扫码 scene → 门店与履约方式 → 菜单分类与加购 → 结算（幂等键）→ 创建订单
→ 订单详情「演示模拟支付」→ 店主订单台接单 → 制作 → 可取 → 完成
```

以及：

- 顾客取消 `PENDING_PAYMENT` 订单（带原因）。
- 店主商品上下架，公开菜单立即变化。
- 演示身份切换（顾客 / 店主 / 店员），店主入口只按后端 `memberships` 出现。
- 店主订单台 10 秒轮询，离开页面停止；可手动暂停。

## 2. 分层铁律如何落地

`docs/component-contract.md` 的约束在实现里对应到具体文件：

| 约束 | 落地方式 |
| --- | --- |
| 页面组合、调用服务层、处理导航 | `pages/*/index.js` 是唯一 `wx.navigateTo / switchTab` 与 `services/*` 调用者 |
| 组件只收 properties、只发 triggerEvent | `components/*/index.js` 不含 `wx.request`、固定路由、`globalData`、服务层 `require` |
| 服务层统一 `wx.request`、Token、错误、超时 | `services/platform.js` 是唯一 `wx.request` 调用点；`services/request.js` 统一鉴权、超时、错误归一化 |
| 领域计算不依赖 `wx` | `domain/*.js` 全部是 CommonJS 纯函数，可在 Node 直接测试 |
| 金额整数分、组件只展示 | 页面与领域层生成 `*Text`；组件只格式化展示，不参与业务计算 |
| Token 不写日志 | `session.js` 只做 storage 读写；全仓库未记录 Token |

组件清单（与页面引用一一对应）：

| 组件 | 用途 | 事件 |
| --- | --- | --- |
| `store-header` | 门店名、营业时间、堂食/自取、桌号 | 无 |

| `product-card` | 商品卡与加减 | `add` / `remove` / `open-detail` |

| `order-status` | 六态徽标与文案 | 无 |

- `empty-state` 由 `state-view state="empty"` 承担，契约 §4 的 `state-view` 是权威组件，避免两套空状态。
- `loading-block` 已独立实现，用于列表骨架。
- 店主订单卡未单独建组件，`order-card` 通过 `role="MERCHANT"` 与 `order.actions` 复用同一结构；契约 §4 允许 `role` 区分，避免重复组件。

## 3. 领域层（可单测的纯函数）

| 文件 | 关键能力 |
| --- | --- |
| `domain/money.js` | `formatCents(2800) → "¥28.00"`、`formatAmount`、`toSafeCents`、`sumCents`；非法输入返回 0，不产生 `NaN` |
| `domain/cart.js` | 不可变购物车；同商品合并；数量 1–99；`cartSummary`；`toOrderItems` 只输出 `productId + quantity`；`mergeCatalogAvailability` 剔除停售并刷新价格快照 |
| `domain/orderStatus.js` | 六态中文文案与色系、进行中/终态判断、顾客可支付/可取消、店主按钮映射（含取消需原因）、进度步骤、列表过滤键 |
| `domain/scene.js` | 解析 `scene` 的 URL 编码 query、纯 `storeId`、`store/s/t` 别名；`resolveEntry` 优先显式 query，其次 scene，最后默认门店 |
| `domain/idempotency.js` | 生成 8–128 位可见 ASCII 的 `idem_*` 键；`isValidKey` |
| `domain/orderView.js` | 订单展示模型：`totalText`、`createdAtText`、`fulfillmentText`、`itemViews`、`progressSteps`、`timeline`、`shortId`；时间固定按 `Asia/Shanghai` 手动偏移，避免设备时区差异 |
| `domain/errorText.js` | 错误码 → 中文文案 + 建议动作；`isAuthError` / `isCatalogError` |

测试：`test/miniprogram-domain.test.cjs`，21 项。

## 4. 服务层与双运行时

### 4.1 请求链路

```text
Page → services/{store,order,merchant,auth}.js
     → services/request.js（鉴权头、Idempotency-Key、超时、401 重登一次）
     → services/platform.js（wx.request 或 Node fetch）
```

- `services/request-core.js` 是纯函数：URL 拼接、query 编码、body 解析、错误归一化、是否需要鉴权重试。可在 Node 测试。
- `services/platform.js` 在检测到 `wx` 时走 `wx.request`；否则走 `fetch`（用于 Node 冒烟）。存储同理：`wx.*StorageSync` 或内存 `Map`。
- `services/session.js` 只存 `{ token, expiresAt, user, identity }`，过期前 60 秒即视为失效。
- 401 会**自动使用当前演示身份重登一次并重放原请求**；重登失败则抛出原始错误，不掩盖后端语义。
- 并发登录在 `auth.ensureLogin` 中去重，避免首页 `onLoad` 与 `onShow` 同时发起登录。

### 4.2 幂等键生命周期

- 结算页首次提交时按 `payload`（含 store、履约、桌号、items、note）生成签名。
- 签名与上次不同 → 生成新 Key；签名相同（失败重试）→ 复用原 Key。
- 创建成功后清空 Key 与购物车。
- 因此：网络失败重试不会重复下单；改购物车后不会撞 `IDEMPOTENCY_CONFLICT`。

### 4.3 错误与恢复

| 错误 | 页面行为 |
| --- | --- |
| `PRODUCT_UNAVAILABLE` | 结算页重新拉目录、剔除停售商品、提示后允许重提 |
| `AUTH_REQUIRED` / `AUTH_INVALID` | request 层自动重登一次；仍失败则提示「重新登录」 |
| `TABLE_REQUIRED` / `TABLE_NOT_FOUND` | 提示扫码或选择演示桌号 |
| `STATUS_CONFLICT` | 店主端自动刷新订单并提示状态已变化 |
| 网络/超时 | 错误条展示，保留输入与幂等键，可直接重试 |

## 5. 状态层

| 文件 | 内容 | 为什么不是 globalData |
| --- | --- | --- |
| `state/visit-store.js` | `storeId / storeName / tableId / tableName / fulfillmentType / 门店履约能力` | tabBar 页面之间无法传参，必须持久化；组件不读，只有页面读 |
| `state/cart-store.js` | 按 `storeId` 隔离的购物车，持久化到 storage | 菜单与结算跨页面共享；切店天然隔离 |

到店上下文规则：

- 扫码 `scene` 带 `tableId` → 默认 `DINE_IN`，桌号按演示桌表映射名称。
- 扫码无桌号 → 默认 `TAKEAWAY`。
- 开发者工具直接打开 → 使用 `DEFAULT_STORE_ID`，默认自取；堂食可选「演示桌号」A01/A02（与种子数据一致）。
- 门店不支持堂食/自取时，自动回退到另一种可用方式。

## 7. 演示登录与环境

- 后端 `.env` 需 `NODE_ENV=development`、`ALLOW_DEMO_LOGIN=true`、`ALLOW_DEMO_PAYMENT=true`。
- 演示身份：顾客 `demo-customer-001`、店主 `demo-owner-001`、店员 `demo-staff-001`，在「我的」页切换。
- 小程序端默认关闭 `wx.login`，使用 `demoOpenId`；需要真实微信登录时设置 `MINIPROGRAM_USE_WECHAT_CODE=true` 并让服务端配置 `WECHAT_APP_ID/SECRET`。
- 微信开发者工具访问 `http://127.0.0.1:3000` 需要勾选「不校验合法域名」。
- 所有支付相关界面固定出现「演示模拟支付」「模拟支付」，不出现「微信支付成功」。

## 9. 已知边界与待补齐

### 9.1 前端已知边界

- 桌号只能来自扫码 `scene` 或演示桌号；没有桌号列表接口，无法在界面里列出真实桌台。
- 顾客订单列表固定按当前门店查询（契约要求 `storeId`），不提供跨店订单聚合。
- 商品图片依赖 `imageUrl`，种子数据为空，当前显示首字占位。
- 订单台轮询固定 10 秒，页面隐藏停止；没有 WebSocket。
- 演示身份切换会重建会话；切换后订单列表按新身份重新查询，购物车不清空。

### 9.2 建议后端后续补齐（已登记到 `docs/后端待实现接口清单.md`）

1. `GET /stores/:storeId/tables`：公开桌号列表（`id/name/sortOrder`），用于堂食选桌和桌号校验前置提示。当前只能扫码。
2. 扫码 `scene` 支持 `tableName`，或在目录接口返回桌号摘要，减少前端兜底。
3. 顾客订单跨店聚合（可选）：`GET /orders` 允许省略 `storeId` 或返回 `storeName` 分组。当前契约要求必填。
4. 订单台增量拉取（可选）：`updatedSince` 或版本号，减少 10 秒轮询全量返回。

## 10. 排查入口

| 现象 | 先看 |
| --- | --- |
| 首页一直 loading | 后端是否启动、`config/env.js` 的 `API_BASE_URL`、开发者工具是否关闭域名校验 |
| 加购后金额不对 | `domain/cart.js` 与 `domain/money.js`；服务端最终计价才可信 |
| 提交总是 `IDEMPOTENCY_CONFLICT` | 检查是否在修改 payload 后复用旧 Key；结算页签名逻辑在 `pages/checkout/index.js` |
| 店主入口不出现 | 后端 `memberships`、当前演示身份、`session.isMerchantOf` |
| 订单台不刷新 | 轮询开关、`onHide/onUnload`、`pages/merchant-orders/index.js` 的 `startPolling` |
| 组件改了样式没生效 | 组件样式默认隔离；共享样式在 `styles/component.wxss`，变量在 `app.wxss` 的 `page` |
| 白屏或配置不生效 | 检查是否有 `.json` 被当作 JS `require`；本项目 require 一律带 `.js` 后缀 |

## 11. 禁止项

- 不改 `templates/mini-program/`。
- 不在组件里加 `wx.request`、固定路由、`globalData` 或服务层依赖。
- 不把单价、总价传给下单接口；金额只由服务端计算。
- 不把演示模拟支付描述为真实微信支付。
- 不把 Token 写入日志、页面 data 之外的可导出全局变量或任何文档。
