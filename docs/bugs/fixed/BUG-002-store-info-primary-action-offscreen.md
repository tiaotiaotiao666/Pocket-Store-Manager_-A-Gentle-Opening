# BUG-002 STORE_INFO 主操作按钮随聊天流滚出视口，流程卡住

- 状态：已修复
- 级别：P1 高
- 发现日期：2026-10-31
- 来源：用户实测
- 影响面：桌面会话工作台 STORE_INFO 阶段

## 1. 现象

用户在 STORE_INFO 阶段填写资料后，无法点击「资料无误，继续」推进流程。页面并未报错、状态机也没有死锁；真正原因是该主操作按钮位于随聊天消息增长的滚动区域内，被内容推到视口之外。

## 2. 根因

阶段推进按钮与聊天流处于同一个滚动容器，消息越多按钮越靠下；用户只能看到聊天记录，主操作不可见，误判为流程卡住。

## 3. 修复

- 将「添加菜品」「资料无误，继续」移入固定的 `.workspace-actions` 区域，不再随聊天流滚动：`src/App.jsx:716`。
- `.workspace-actions` 使用 `flex: none` 固定在输入区上方：`src/styles/panel.css:36`。
- 请求进行中禁用推进按钮；资料齐全后才允许确认。

## 4. 验证

| 证据 | 结果 |
| --- | --- |
| 代码结构 | 主操作位于固定 flex 区域，外层滚动只作用于消息区 |
| `npm test` | 100/100 通过（状态机无死锁） |
| 人工点击级复验 | 交接文档记录为已修复，未形成截图证据 |

## 5. 防回归

新增阶段的主操作按钮一律放入 `.workspace-actions`，不得放进消息滚动容器。桌面端结构约束见 `docs/面向AI的桌面端构建文档.md`。
