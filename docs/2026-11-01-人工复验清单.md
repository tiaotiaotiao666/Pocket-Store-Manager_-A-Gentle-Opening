## 一、启动前置（PowerShell）

工作目录：`E:\智能开店app`。本项目 shell 预设了 `ELECTRON_RUN_AS_NODE=1`，必须先清掉，否则 Electron 会以纯 Node 运行并在启动时抛错。

```powershell
$env:ELECTRON_RUN_AS_NODE = $null
npm run desktop:dev
```

- 网络相关：M8/M9 是纯本地导出与校验，**不需要后端**。M8 的体检不含后端存活检查，后端没起不影响本清单判定。
- 改过 `desktop/*.cjs` 或 `desktop/preload.cjs` 后必须**完整关闭窗口再启动**，只刷新渲染层不生效。
- 证据截图统一放 `docs/evidence/p0-closeout/manual/`，命名与组号对应（如 `BUG018-before.png`、`M8-appid.png`）。
- 使用**专用测试项目**做导出与冲突实验，不要动工作区里唯一真实项目。

## 二、复验组 1：BUG-018 空项目点「轻启」应直接复用

**为什么还没验**：修复已提交（`9828dfc`），`hasProjectContent` 判空逻辑由 `test/session-machine.test.cjs` 覆盖，但界面点击未复验。

**前置**：准备一个「空项目」——新建后不填店名、不选模板、不写提示词、没有图片、没导出过。

**步骤**：

1. 打开工作台，进入这个空项目（点开后停在命名/会话页均可）。
2. 点左侧栏「轻启」。
3. 观察是否弹「开始一个新项目？」确认框。

**预期**：**不弹确认框**，直接进入命名引导，并且当前活动项目**还是原来那个空项目**（不新建第二个）。

**反向验证（很重要，防止改过头）**：换一个**有内容**的项目（有店名，或选过模板，或有图片/导出记录），重复第 2 步。

**预期**：应弹出「开始一个新项目？」确认框；点「取消」后仍留在当前阶段，不能被拉回功能选择页。

**失败时回报**：写清是「空项目仍弹框」还是「有内容项目不弹框」，附截图；不要自行改代码。

## 三、复验组 2：BUG-014 流程中点「轻启」不应被拉回功能选择页

**为什么还没验**：BUG-014 修复已通过自动化，但「项目流程内点轻启」这一具体路径未单独复验。

**前置**：一个已有内容的项目，停在**店铺装修**或**部署**阶段。

**步骤**：

1. 在店铺装修页（或部署页）点左侧栏「轻启」。
2. 看是否弹确认框。
3. 点「取消」。

**预期**：弹出确认框；取消后**仍停在原阶段**，页面内容、已填资料、会话记录都不丢；不出现被拉回功能选择页的情况。

**补充**：若点「确认」，预期是新建一个项目，旧项目内容不被清空（可从工作台切回验证）。

## 四、复验组 3：门店图片入口 + A-UI-1 缩略图三类项目

**为什么还没验**：入口代码已接通（`StoreInfoStep` 门片图片区块 → `pickImages → attachImages → ADD_PROJECT_IMAGES → 自动保存`），但界面复验从未单独记录。

**步骤**：

1. 进入项目 → 店铺信息页 → 找到「门店图片」区块 → 点「添加门店图片」，选 1–2 张 PNG/JPG/WebP。
2. 回工作台，看该项目卡片。
3. 再准备/观察两类项目：**无图项目**、**图片文件已缺失的项目**（在项目数据目录里删掉对应资产文件后刷新列表）。

**预期**：

- 有图项目：卡片显示**第一张真实图片**，不是首字渐变，无破图图标。

- 图片缺失项目：回退首字，不显示破图，刷新后仍可重试。

## 五、复验组 4：A-UI-2 / A-UI-3 同名冲突、更换目录、重启

**为什么还没验**：A-UI-2 用户曾实测换目录，但没记录新目录与导出结果，按计划不能判 PASS；A-UI-3 从未执行。

**前置**：任意已完成体检、资料齐全的项目；一个临时导出目录，如 `%TEMP%\smartstore-recheck\`。

**步骤（A-UI-2）**：

1. 在临时目录里先手工建一个与项目名同名的空目录。
2. 在部署页体检，然后尝试导出。
3. 出现冲突后点「更换目录」，选另一个可写目录，再导出。

**预期**：出现 `E-TARGET-EXISTS`（或等价冲突文案）；原目录内容不变；冲突时不可直接导出但可换目录；换目录后能正常导出。

**步骤（A-UI-3）**：

1. 保持上一次的导出目录配置不变（旧目录里仍有同名工程）。
2. 完整关闭应用，按第一节命令重启，重新打开该项目进入部署页。

**预期**：能正常进入部署页；不出现因 error 卡死无法换目录；状态不卡在 `choosing` / `validating`，不残留 `busy: true`。

**失败时回报**：写清卡在哪个状态、按钮是否可点、控制台是否有报错。

## 六、复验组 5：M8 导出 + AppID 后置写入

**为什么还没验**：导出链路已在批次 A 走通，但「AppID 后置写入」这一条没有独立证据。

**步骤**：

1. 在部署页把项目导出到工作区外临时目录（如 `%TEMP%\smartstore-recheck\`）。
2. 进入交接向导第 3 步，写入一个**格式合法但非真实**的 AppID：`wx` + 16 位十六进制，例如 `wx0123456789abcdef`。
3. 打开导出工程，对比 `project.config.json` 与 `appid-postprocess.json`；再全局搜索工程内是否出现 AppID 明文。

**预期**：

- 工程 `project.config.json` 的 AppID 等于填写值。
- `appid-postprocess.json` 只含掩码 / 哈希，**无明文 AppID**。
- 写入后产物摘要按既有口径重算，不报错。

**记录要求**：报告中只写掩码，不公开完整 AppID。

## 七、复验组 6：M9 产物一致性校验 `composer:verify`

**为什么还没验**：命令与契约已就绪，从未在真实导出产物上跑过「改坏 → 报错 → 恢复 → 通过」的闭环。

**步骤**：

1. 复用组 5 的导出工程，复制一份作为实验副本。
2. 在副本里手工修改 `app.json` 一个字符（例如改一个页面路径的字母）。
3. 在仓库根执行（PowerShell 下注意引号）：

```powershell
npm run composer:verify -- --root "<导出工程绝对路径>" --mode development
```

4. 把 `app.json` 改回原样，再执行一次。

**预期**：

- 第一次：退出码非 0，报告明确指出失配项。
- 第二次：退出码 0，校验通过。

**禁止**：为通过校验去改仓库内模板或注册表；不要动 `templates/registry/`。
