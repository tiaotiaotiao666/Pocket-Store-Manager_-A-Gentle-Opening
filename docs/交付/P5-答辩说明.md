# P5 答辩说明

## 1. 背景与问题

餐饮小店要做小程序，通常要经历「找人写、反复改、交付一个看不懂的工程」三步，成本高、不可控。本项目把它变成**会话式生成**：店主用自然语言描述门店与菜品，客户端把需求变成一份被校验、被摘要锁定的工程计划，最后由确定性 Composer 生成完整小程序工程。

一句话定位：**AI 负责理解，规则负责生成，人在关键节点确认。**

## 2. 架构

```
Electron 客户端（React + Vite）
  ├─ 会话状态机：home → onboarding → features → building → template-pick
  │                 → store-info → prompt-studio → image-review → deploy
  ├─ 服务端 Agent 调用（POST /api/v1/agent/run，契约 agent-run.v1）
  ├─ 模板注册表（templates/**，带摘要冻结）
  └─ 主进程 IPC：项目读写、导出、AppID 回填、预览、诊断
NestJS 服务端（server/）
  ├─ Agent 编排：模型调用 + 工具白名单（读/写门店资料、校验、图片输入）
  ├─ Prisma + MySQL：门店、分类、菜品、桌台、海报模板
  └─ readyz：数据库与缓存真实探活
Composer（scripts/composer）
  └─ plan.json → 校验 → 生成工程 → output-lock/report 摘要
```

关键设计：**模型不直接写文件、不直接写库**。模型只能产出结构化的草稿；落库与生码分别由白名单工具和 Composer 完成，且 Composer 的输入是一份可被摘要校验的 plan。

## 3. Agent 的工具调用

- 一次门店资料填写实测：`modelCalls=3`、`toolCalls=2`（读取门店资料 → 更新门店资料 → 校验信息），全部成功，草稿从 0/5 到 5/5。
- 工具集是白名单：读门店资料、写门店资料（带字段级校验）、校验资料完整性、图片输入（识别）。没有「执行任意代码」「任意写文件」这类工具。
- 每一次运行都有 `requestId` 与 `runId`，日志里可回放 `status / stopReason / modelCalls / toolCalls / failedTools`。

## 4. 白名单与安全边界

| 边界 | 做法 |
| --- | --- |
| 模型输出 | 只作为草稿，字段级校验（长度、取值范围、必填） |
| 工具 | 白名单，无任意执行能力 |
| 跨域 | 服务端 `allowedHeaders` 显式列举；有回归测试防止漏项（本轮就修过 `X-Request-Id` 缺失导致真实 POST 被拦） |
| 导出 | 只写用户选择的本地目录，不联网、不上传、不发布 |
| 密钥 | 只在 `server/.env`，不进前端、不进导出工程、不进仓库 |
| 能力勾选 | 「导入微信开发者工具」等外部能力必须人工确认，界面不代替你点 |

## 5. 项目恢复

- 每个门店一个项目目录，资料、图片、会话、导出进度全部本地落盘。
- 实测：关闭客户端并重启后，项目列表仍是 12 个项目，打开其中一项回到上次阶段（店铺装修）与已保存的门店名。
- 项目保存有 flush 守卫：退出前会把未落盘的会话状态刷掉，避免「关窗口丢进度」。

## 6. 真实验证结果（详见证据索引）

- 桌面主流程 CDP 真实点击走查：**13 项 PASS / 0 FAIL / 2 BLOCKED**（生图未接入、导出需原生对话框）。
- 重开恢复：3 项 PASS。
- 导出：Composer 真实产物 138 文件，`output-lock.json` 与 `appid-postprocess` 双重摘要校验通过；写真实 AppID 后 `verified: true`。
- 回归：`npm test` 789/789；vite 构建通过；注册表 / 组件目录 / 小程序镜像 / 镜像一致性全部通过；服务端构建通过，19 个套件 296 项通过，6 个数据库套件因账号无 `CREATE DATABASE` 权限在准备阶段失败（前置条件已写清，未隐藏）。

## 7. 局限（不粉饰）

1. **生图未接入**：海报素材一步无真实图像生成，界面如实说明。
2. **参考截图识别依赖上游视觉模型**：本次实测上游 502，界面如实报错、不产假候选。
3. **导出到指定目录需要原生对话框**：自动化走查只能点到按钮，无法在系统对话框里选目录；已在命令行用同一 Composer 通道复核产物。
4. **数据库测试前置**：需要可建库的 MySQL 账号。
5. **真机/发布未验证**：未真机预览、未发布体验版。
6. **华为云未开通、未验证，非本次演示依赖。**
7. **支付是演示模拟**（`DEMO_PAID`），无真实支付通道。
8. 设置文件读取失败时会弹「已保留备份并恢复默认设置」——功能不阻断，但提示文案偏技术化，后续要改。

## 8. 后续规划

1. 接入真实生图服务，把海报素材从「可跳过」升级为「可生成 + 可重生成」。
2. 视觉识别做多供应商降级（主备模型 + 超时退避），把 502 从失败变成可重试。
3. 导出目标目录支持「记住上次位置 + 命令行/配置文件指定」，减少人工点击。
4. 数据库测试提供容器化 MySQL 或临时账号，做到 CI 全绿。
5. 华为云与真实支付作为独立里程碑，先做沙箱与合规评估，再谈接入。

## F1 增补：最终验收口径（2026-11-19）

一句话结论：**主线真实可跑、可演示到「本地工程 + AppID + 交付清单」；微信端真实运行与发布因本机没有开发者工具，按 BLOCKED/NOT_RUN 如实交代。**

可以正面回答的四件事：

1. 资料是真实模型整理出来的，跨夜营业时间、两段午休、撤销修改都是真实数据流转，不是演示脚本硬编码。
2. 「预览」和「采用」被严格分开：点卡片只预览，徽标与当前版本不动，点「就用这套」才切换；两套模板是结构不同，同组配色不算模板。
3. 导出前摘要就是实际要生成的内容，改资料或换位置后旧体检立即失效，同名目录不会被覆盖；普通流程不出现技术码，也不要求逐条勾选确认。
4. 不夸大能力：海报生成按钮 disabled 并说明未接入生图服务（P5 时点；G1 已接入真实生图，见文末增补）；导出只写本地、不上传不发布；预览是 React 复刻，真实渲染要以微信工具为准。

需要主动交代的三个边界：

1. 本机没有微信开发者工具 → 首页/菜单/菜品/结算/桌号/加购/订单/演示支付的真实微信运行、真机预览、体验版发布、真实支付全部未执行。
2. 本机工作区默认导出目录存在环境级 `rename EPERM` 看守（P5c 已记录同一限制），验收用 `SMARTSTORE_EXPORT_DIR` 换到可写目录，按钮/IPC/Composer/AppID 后处理仍是线上那一套。
3. 参考截图识别链路本轮未执行（入口是主进程原生文件对话框，自动化无法驱动），不拿 P5b 的历史结果冒充当轮证据。

门禁：root `npm test` 1054/1054；server vitest 571/571（需用有 `mysql` 库权限的测试连接）；vite build、nest build、契约 `--check`、registry/catalog/frontend-capabilities/mini/mirror/packaging、Composer 产物校验、`git diff --check` 全通过。

证据索引：`docs/交付/evidence/f1-acceptance.json`、`docs/交付/evidence/f1-export-tree.txt`、`docs/交付/evidence/f1-shots/`、`docs/交付/F1-最终验收报告.md`。

## G1 增补：真实 AI 生图闭环（2026-11-19）

一句话结论：**海报素材不再是「只能跳过」，而是真的调第三方生图服务出图，并一路走到导出工程的首页主图。**

可以正面回答的四件事：

1. 真实调用：模型 `gpt-image-2.6`，同步接口，单张 38–43 秒，返回 base64 PNG；请求 `1024x1024` 实际给 `1254x1254`，入库前缩到 1024 边、2 MB 以内。
2. 成本与安全：默认每次 1 张（不强制 n=2）、并发 1、10 分钟最多 6 次、超时 120 秒；密钥只在 `server/.env`，不下发界面、不进日志、不写导出工程；不带密钥的匿名调用直接被上游 401 拒绝（说明不会替别人花钱）。
3. 全链路闭合：改提示词 → 真实生成 → 预览 → 选用 → 重开项目仍能预览 → 导出工程 `assets/media/home-background.png` 与资产库同一份字节（`sha256:720b75c4…`），首页 `pages/home/index.wxml` 真实引用，工程 README 记录来源/提供方/模型/摘要。
4. 不夸大：只有真实拿到合法 PNG 才显示「AI 生成成功」；失败保留原素材与提示词并可重试/跳过；用户上传的图仍标「用户上传」，不冒充 AI 生成。

需要主动交代的边界：

1. 微信开发者工具真实导入与截图仍未执行（本机无工具，BLOCKED）。
2. `npm run agent:smoke` / `agent:snapshot` 本机 UIA 返回 `拒绝访问 (os error 5)`，BLOCKED；界面改动用 CDP 真实点击走查覆盖。
3. 本机工作区目录保护会让 Composer 的原子目录改名返回 `EPERM`，导出验证改用工作区之外的应用数据目录（逻辑与校验未放宽）。
4. 生图只覆盖海报素材这一步，不生成整站前端；华为云、真实支付、发布能力均不主张。

门禁（G1 本轮实跑）：root `npm test` 1066/1066；server `npx vitest run` 583/583；`vite build`（`TEMP/TMP` 需指向工作区之外）、契约 `--check`、registry/catalog/frontend-capabilities/mini/mirror 与 `git diff --check` 全通过。

证据：`.arts/g1/evidence.md`（脱敏：端点/模型/状态/耗时/字节/摘要/导出落位，不含密钥与 base64）。
