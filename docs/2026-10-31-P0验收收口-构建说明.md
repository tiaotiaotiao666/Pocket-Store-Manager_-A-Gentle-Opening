## 三、F1 导出目标冲突预检

### 3.1 主进程 IPC 契约

通道：`composer:preflight-target`（`desktop/composer-ipc.cjs`）。

请求：

```json
{
  "parentDir": "C:\\Users\\example\\AppData\\Local\\Temp\\smartstore-p0",
  "projectName": "松月食堂"
}
```

成功返回：

```json
{
  "ok": true,
  "exists": false,
  "projectName": "松月食堂",
  "suggestedName": null
}
```

冲突时返回 `ok: true`、`exists: true`，并给出只读计算的 `suggestedName`。

失败返回 `ok: false` 与稳定错误码：

| 错误码 | 触发条件 |
| --- | --- |
| `PAYLOAD_TOO_LARGE` | payload 超过 256 KB |
| `TARGET_PARENT_MISSING` | 未选择父目录、父目录不存在或不是目录 |
| `TARGET_PATH_INVALID` | 路径解析失败或清洗后越界 |
| `TARGET_CHECK_FAILED` | stat / exists 检查异常 |
| `UNTRUSTED_SENDER` | 非 file:// 或 `http://127.0.0.1:5173` 来源 |

### 3.2 只读与安全约束

- 复用 `scripts/composer/atomic.cjs` 的 `sanitizeProjectName` 与 `suggestName`，不复制规则。
- 不调用完整 `preflight()`，不使用 `canWrite()`（它会创建并删除 probe 文件）。
- 只做 `path.resolve` / `path.join` / `fs.statSync` / `fs.existsSync`。
- 不创建父目录、目标目录、staging、probe 或报告，不调用 `compose`。
- 不因预检成功写入 `exportedOutputs`。
- preload 只新增 `composerPreflightTarget(payload)`，不暴露 `ipcRenderer` / `fs`。

### 3.3 服务层

`src/services/exportService.js` 新增 `preflightTarget({ parentDir, projectName })`：

| 返回 status | 含义 |
| --- | --- |
| `ok` | 目标不存在，可以继续 |
| `conflict` | 目标已存在，带 `suggestedName` |
| `failed` | 检查失败，必须阻断；IPC 抛异常也归入此类 |
| `desktop-required` | 浏览器模式或桥接缺失 |

新增错误文案：`TARGET_PATH_INVALID`、`TARGET_CHECK_FAILED`。

### 3.4 规则合并

`src/domain/preflightRules.mjs` 新增：

- `TARGET_RULE_IDS.CONFLICT = 'E-TARGET-EXISTS'`
- `TARGET_RULE_IDS.CHECK_FAILED = 'E-TARGET-CHECK-FAILED'`
- `mergeTargetPreflight(local, targetResult)`

行为：

- `exists: true` 或 `status: 'conflict'`：追加且只追加一条 `E-TARGET-EXISTS`，`fieldPath = deploy.projectName`，文案含“不会覆盖”与建议名。
- `status: 'failed'` / `desktop-required`：追加 `E-TARGET-CHECK-FAILED`，`fieldPath = deploy.directory`，阻断导出。
- `status: 'ok'` / `exists: false`：不产生 error。
- 重复合并不产生重复行。
- 两个规则 ID 已加入 `PREFLIGHT_RULE_IDS.ERROR`。

### 3.5 门禁与防死锁

`src/state/sessionMachine.mjs` 新增 `selectCanChooseDirectory(state)`：

- 浏览器模式、体检中、体检失败、未完成体检：不可选。
- 除 `E-TARGET-EXISTS` 外还有其他 error：不可选。
- 有未确认 warn：不可选。
- 唯一阻断是 `E-TARGET-EXISTS`，或没有任何阻断：可选。

`selectCanExport` 语义未改：只要存在 `E-TARGET-EXISTS` 仍然不可直接导出。

### 3.6 App 接线

`src/App.jsx`：

1. **常规体检**：本地规则与 Composer validate 后，若桌面模式、已有 `deploy.directory` 且项目名非空，调用 `preflightTarget` 并合并；未选择目录不伪造路径。
2. **导出前二次预检**：`runDeployExport` 在 `exportProject` 前再检查刚选择的目录；冲突时更新体检面板并进入 `DEPLOY_CONFLICT`，失败进入 `DEPLOY_FAILURE`，都不调用 Composer。
3. **按钮门禁**：`handleDeployChooseDirectory` 与 `handleDeployRetry` 使用 `selectCanChooseDirectory`；`DeployStep` 的 `blockedReason` 改由该判断提供。
4. **竞态保护**：Composer 自身 `TARGET_EXISTS` 仍保留为最终保护，未删除。

`src/components/build/DeployStep.jsx` 未改，现有 props 足以表达“不可直接导出但可换目录”。

## 四、F2 工作台真实缩略图

### 4.1 新增加载器

`src/services/projectThumbnailLoader.js`：

```text
createProjectThumbnailLoader({
  readAsset,          // (projectId, assetId, maxWidth) => Promise
  concurrency = 4,
  maxCacheEntries = 100
})
```

返回：

- `load(projects) => Promise<{ [projectId]: dataUrl | null }>`
- `clear()`
- `getCacheSize()` / `getConcurrency()`（只读，供测试与诊断）

行为：

1. 只处理非空 `projectId + thumbnailAssetId`。
2. 缓存键 `${projectId}:${assetId}`；换资产自然换键。
3. 同键进行中请求复用同一 Promise。
4. worker 队列限制全局并发，默认 4。
5. 单图 reject / 非 ok / 空 `dataUrl` 只让该项返回 `null`，不拖垮整批。
6. 成功结果才进缓存；失败不缓存，刷新可重试。
7. Map 顺序实现 LRU，超过 100 条淘汰最旧。
8. `clear()` 递增 generation，旧请求完成时不会写回缓存。
9. 不直接访问 `window.smartStore`，`readAsset` 由 App 注入。

### 4.2 App 接线

`src/App.jsx`：

- 用 ref 持有 loader，用 state 保存 `thumbnails` 映射，不新增持久化 reducer 切片。
- 监听 `state.project.list` 变化触发批量加载；列表为空或浏览器模式置空映射。
- effect 使用 `alive` 标记，卸载或列表变化后旧批次不覆盖新列表。
- 合并时只保留当前列表仍存在的项目，已删除项目自动清理。
- 将 `thumbnails` 传给 `ProjectWorkbench`，接通已有 props。

### 4.3 卡片渲染

`src/components/workbench/ProjectCard.jsx`：

- 保留 `thumbnail ? <img> : 首字` 回退结构。
- `<img>` 增加 `loading="lazy"`、`decoding="async"`。
- `onError` 时置 `imageFailed`，回退首字，不出现破图循环；缩略图变化时重置失败标记。
- `alt=""` 保持不变，店名已在正文中。

### 4.4 边界

- 缩略图只存在于 React 内存与 loader 缓存。
- 不写入 `project.json`、localStorage、撤销/重做历史或导出工程。
- 未改 `desktop/asset-store.cjs`、`desktop/project-store.cjs`、`projectService.js`、`ProjectWorkbench.jsx`、`store.generated.js`。
- 用户图片仍不进入导出工程。

### 4.5 图片来源入口（F4 补充）

F4 发现工作台缩略图缺少图片来源，按用户确认补最小入口：

- `src/components/build/StoreInfoStep.jsx` 新增“门店图片”区块：显示已添加数量、文件名、尺寸/大小，最多 6 张。
- `src/App.jsx` 新增 `handlePickStoreImages`：桌面模式且已有 `project.activeId` 时调用 `pickImages(6)` → `attachImages(projectId, tokens)` → dispatch `ADD_PROJECT_IMAGES`。
- `src/state/sessionMachine.mjs` 新增 `ADD_PROJECT_IMAGES`：按 `assetId` 去重、最多 6 张、空输入返回原 state。
- 浏览器模式、无项目、已满 6 张时给出明确提示，不调用主进程。
- 图片仍只作为项目资产，不进入导出工程；`attachImages` 已按 sha256 去重落盘。
- 自动化只覆盖 reducer 合并去重与上限；Electron 文件对话框与工作台实际缩略图仍需人工验证。

## 六、启动桌面应用时的环境问题（已绕过）

当前 shell 预设 `ELECTRON_RUN_AS_NODE=1`。直接运行 `npm run desktop:dev` 会让 Electron 以纯 Node 执行 `desktop/main.cjs`，在第 16 行 `app.getPath('userData')` 抛：

```text
TypeError: Cannot read properties of undefined (reading 'getPath')
```

正确命令：

```bash
env -u ELECTRON_RUN_AS_NODE npm run desktop:dev
```

这不是代码缺陷，也未修改任何应用配置。2026-10-31 21:28:58 已用该命令启动，主窗口 PID 23932，Vite 5173 正常。
