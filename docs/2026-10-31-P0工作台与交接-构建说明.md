## 三、架构与关键实现

### 3.1 `view` 与 `phase` 分层

- `state.view = 'workbench' | 'flow' | 'settings'`，`phase` 仍是九阶段。
- `App.jsx` 在 hooks 之后按 `view` 提前 return；`renderStage()` / `buildPanelCards()` 未改。
- 工作台与设置页是全宽页面（不使用 AppShell 的三栏），状态更舒展。

### 3.2 `project.json` 是唯一真相源

- 渲染层只在内存投影；保存由 `toDocument(state)` 生成，主进程 `normalizeDocumentForSave` 再做顶层白名单与 `updatedAt` 回填。
- 图片不内联：`visual.imageAssetId`、`store.logoAssetId`、`store.imageAssetIds` 指向 `assets/images/*`。
- transient 清单：`deploy` 的进度/错误/导入预览、`agent` 的派生量、`sessions[].revealFlush`、消息动画字段、`visual.image.dataUrl`。
- 未知顶层字段保存时归入 `unmappedFields`，读取时再视为未知，保证旧版本打开新项目不丢字段。

### 3.3 写盘

- 每项目一条写队列：覆盖式合并 pending；被覆盖的调用方拿 `superseded` 回执，`await` 不会挂起。
- 原子写：tmp → fsync → rename；Windows 不能 rename 覆盖，所以先 `target → target.old`，再 `tmp → target`，再删 `.old`，失败回滚。
- 保存前备份当前 `project.json` 到 `backups/project.<n>.json`，环形保留 `maxBackups`。
- 损坏三级降级：主文件坏 → 最近可解析备份；备份也坏 → 原文件改名 `project.corrupt.<ts>.json` + 空白项目；高版本 → `futureVersion` 只读标记。
- 关窗握手：`before-quit` 发 `project:flush-request`，等 renderer `project:flush-done` 或 3s；启动时 tmp 自愈。

### 3.4 图片两段式

1. `project:pick-images`：系统对话框 → 只返回 `{ token, name, bytes, mime, width, height }`。
2. `project:attach-images`：主进程校验 token → 读文件 → magic 判类型 → sha256 去重 → 落盘。

这样渲染进程拿不到外部绝对路径，IPC 体积从「几 MB × 6」降到几百字节。缩略图用 Electron `nativeImage`（最长边 320，JPEG 0.82）；Node 测试不传 adapter 时返回原图（≤1.5 MB）。

### 3.5 自检分工

- 主进程：运行时版本、userData 可写/剩余空间、Composer 注册表冻结完整性。
- 渲染层：`GET {apiBaseUrl}/health`、`GET {apiBaseUrl}/readyz`，区分 network / cors / http-5xx；`/readyz` 503 只降为 warn（数据库不可用 ≠ 服务不可用）。
- 模型通道：`mock` 直接通过；`http` 只检查端点格式 + 后端可达，**不发起真实 turn**（不消耗额度）。

### 3.6 体检门禁

- 先本地规则（店名、菜品数/价格、营业时间、取餐方式、AppID、浏览器模式）。
- 无 error 且桌面模式才调 `composer:validate`（P0–P2，不写盘）。
- `previewOnly` / `updatesAvailable` 转 warn；error 阻断、warn 必须勾选、info 折叠。
- 进入 deploy 且状态 idle/cancelled/failed 时自动体检一次；离开展开阶段重置守卫。

### 3.7 AppID 后置写入（D-1）

关键结论（不可省略）：

- Composer 的 `outputDigest` 覆盖 `project.config.json`，直接改写会让 `composition.lock.json` 与 `generation-report.json` 自相矛盾。
- 回填必须用**清单口径**：只对 `lock.outputDigest.files[].path` 重算；`tree'` 按与 `treeSha256` 同款文本归一化构造；**不能对整目录重算**（lock/report 在 verify 之后才写，整目录必然不等）。
- 步骤：备份三文件 → 改写 → 重算 → 更新 lock（`lockDigest` 自洽 + `validateLock`）→ 更新 report（tree/files/fileCount/lockDigest）→ A1–A8 → 侧车 `appid-postprocess.json`（掩码 + 哈希，不含明文）。
- 失败全量回滚；回滚失败返回 `details.backupDir`。
- 语义变化写进向导：相同方案 + 相同模板版本 + 相同 AppID → 相同工程与 lockDigest；换 AppID 只改产物指纹。

### 3.8 支付结果页

- 不新增页面：`pages/order-detail` 内四态视图，避免改 `app.json` / Base `pages[]`。
- `success` 仅在服务端重新拉单后 `paymentStatus === 'DEMO_PAID'` 且未取消时成立。
- `pending` 对应已提交但未落库/未确认；`error` 保留 `requestId` 与重试。
- 商家从 `?pay=1` 进入 → `redirectTo /pages/merchant-orders` + toast；从订单列表进入（无 pay）行为不变。
- 取餐号直接复用 `orderView.shortId`（订单 id 末 6 位大写），文案标「演示」。

### 3.9 撤销/重做

- 实现位置：`sessionMachine.mjs` 的 `reducer` 包装层，语义动作前压快照；`UNDO_APPLY / REDO_APPLY` 由包装层管理栈。
- 快照只含 `store / features / build.selectedId / visual / agentDraft / appid`；`phase`、会话、deploy 不回退。
- 栈深 20，不持久化；同一动作名 + 同字段连续触发只压一次（无时间戳，保持 reducer 纯函数）。
- 快捷键 Ctrl+Z / Ctrl+Shift+Z，仅在 flow 且焦点不在输入框时生效。

### 3.10 RESET 双语义

- `RESET`：保留旧语义（全新空白状态），既有测试与行为不变。
- `RESET_PROJECT`：UI 使用；重置当前项目内容，保留 `projectId`、`createdAt`、`appid`、列表与设置，并标记 dirty。

## 五、容易被误判的实现细节

1. **`project.json` 的 `updatedAt` 由主进程回填**：渲染层传的快照时间会被覆盖，这属于预期。
2. **`agent.status` 不持久化**：只持久化 `agentConfirmedSeq`；重启时 `readyForReview` 为真才恢复 `confirmed`，避免卡在 `requesting`。
3. **hydration 降级**：`building → features`；`image-review` 无效果图 → `store-info`；避免重启触发重复生图/构建。
4. **`config/store.generated.js` 的 `meta.lockDigest` 与 `composition.lock.json` 的 `lockDigest` 本来就不等**：前者是配方阶段，后者含 `outputDigest`。AppID 回填只改 lock/report，不改 `store.generated.js`。
5. **浏览器模式**：项目存 localStorage，图片不落盘，导出与 AppID 写入均 `DESKTOP_REQUIRED`；设置、诊断可读 localStorage/HTTP。
6. **工作台的「删除」不是一键撤销**：必须手动输入项目名前缀完全一致；主进程二次校验；移动到 `projects-trash/`。
7. **开发者工具只探测、不拉起**：CLI 服务端口当前不可用；向导按钮降级为「复制安装说明」。

## 八、开发者怎么跑

# 桌面（开发）

npm test
npm run test:desktop

npm run mini:smoke     # 需要后端 127.0.0.1:3000
