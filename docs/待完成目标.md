### 0.3 完全未开始

- 后端业务域（门店 / 菜单 / 订单 / 鉴权 / Redis 缓存 / MySQL 持久化）。
- 顾客端与店主端的真实点餐闭环。

### 0.4 路线差异（必须先统一）

- **需求文档路线**：一套后端 + 小程序，按 `storeId` 隔离多店，跑通「店主配置门店 → 顾客扫码下单 → 店主看单」闭环。
- **上一轮实现路线**：本机桌面生成器，导出「独立小程序工程」，不含线上订单后端。
- 差距判断：两者可合并——生成器负责产出结构化门店配置并可选落库，后端负责订单闭环，小程序承载顾客与店主操作。**该合并方向需在 M0 确认。**

## 3. 关键验收清单（对齐 `docs/order-state.md`）

- [ ] 六态：`PENDING_PAYMENT → PENDING_ACCEPT → PREPARING → READY → COMPLETED`，另有 `CANCELLED`。
- [ ] 模拟付款仅订单本人、仅 `PENDING_PAYMENT`，转 `PENDING_ACCEPT` + `DEMO_PAID`；重复调用幂等。
- [ ] 店主不得处理 `PENDING_PAYMENT`（`409 MERCHANT_CANNOT_HANDLE_UNPAID`）。
- [ ] 顾客不得修改已付款订单；不得跳过/回退状态。
- [ ] 幂等：同用户 + 同门店 + 同 `Idempotency-Key` 复用返回原订单，payload 不同返回 `409 IDEMPOTENCY_CONFLICT`。
- [ ] 状态更新使用事务 + 条件更新（受影响行数为 0 → `409 STATUS_CONFLICT`），每次成功写一条状态记录。
- [ ] 生产环境模拟登录/模拟付款一律 `403`。
