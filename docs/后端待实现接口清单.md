# 桌面生成器云端接口清单（后续阶段）

> 本文只覆盖桌面生成器的项目/会话、候选、提示词、生图和部署接口，不是点餐业务后端的首期清单。统一路线、先后顺序和实施套餐见 [`后端实现方案与套餐.md`](后端实现方案与套餐.md)；顾客/店主 API 契约见 [`api.md`](api.md)。当前列出的能力尚未实现，桌面端由 `src/services/agentService.js` 本地占位模拟。
> 技术栈约定：NestJS 模块化 + MySQL（RDS）+ Redis（DCS），API 使用 `/api/v1` 版本化风格；订单/商品金额以整数「分」存储与传输，金额由服务端计算。

## 1. 通用约定

- Base URL：`/api/v1`，JSON，`camelCase`。
- 认证：店主登录后 `Authorization: Bearer <JWT>`。
- 错误结构：

```json
{ "code": "PROMPT_ROUND_INVALID", "message": "人类可读说明", "details": {} }
```

- 幂等：创建类请求支持 `Idempotency-Key` 头。
- 分页：`page` / `pageSize`，响应 `{ items, page, pageSize, total }`。
- 时间：ISO 8601 字符串。
- 金额：整数分（如 `2800` 表示 28.00 元），前端不传总价。
- 长任务：统一异步任务模型 `{ taskId, status, progress, result?, error? }`，状态 `queued | running | succeeded | failed | canceled`。

  id CHAR(26) PRIMARY KEY,

## 7. 生图任务与审核迭代

前端调用：`generateImage` / `reviseImage`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/generation/images` | 创建生图任务 |
| GET | `/api/v1/generation/images/:imageId` | 查询任务状态 |
| POST | `/api/v1/generation/images/:imageId/rounds` | 基于修改意见重新生成 |
| GET | `/api/v1/generation/images/:imageId/rounds` | 迭代历史 |

创建响应：

```json
{ "imageId": "01J...", "status": "queued", "progress": 0 }
```

完成响应：

```json
{
  "imageId": "01J...",
  "status": "succeeded",
  "progress": 100,
  "imageUrl": "https://obs.example.com/...",
  "provider": "huawei-modelarts",
  "note": "按提示词生成"
}
```

建议：

- 图片存 OBS，返回可过期签名 URL；不要把 base64 长期存 DB。
- 前端轮询或 SSE；任务状态写 Redis。
- 上传门店参考图前必须让用户显式确认；参考图同样走 OBS。

## 10. Redis 用途建议

- 会话当前 phase 与最近消息缓存（降低 MySQL 读压力）。
- 异步任务状态与进度（TTL 与任务生命周期一致）。
- 幂等键（`Idempotency-Key` → 结果）。
- 接口限流（按 owner / IP）。
- SSE 事件通道（如需实时进度）。

## 11. 任务状态与前端 phase 映射

| 后端状态 | 前端 phase | 说明 |
| --- | --- | --- |
| 模板任务 `queued/running` | `building` | 显示构建加载页 |
| 模板任务 `succeeded` | `template-pick` | 展示候选 |
| 提示词任务进行中 | `prompt-studio` | 工作台忙碌态 |
| 生图任务 `queued/running` | `image-review`（busy） | 三点加载 |
| 生图任务 `succeeded` | `image-review` | 展示效果图 |
| 部署 `running` | `deploy` | 进度条 |
| 部署 `succeeded` | `deploy` | 成功卡片 |

## 12. 安全与合规

- 模型密钥、OBS 凭证、数据库密码只放服务端环境变量，禁止进入仓库或前端。
- 门店参考图上传前必须用户确认；明确告知发送范围。
- 不代办微信主体注册、认证、审核、发布。
- 会话与图片按 owner 隔离，接口需校验归属。
- 日志脱敏，不记录完整提示词中的敏感经营信息（可按需保留摘要）。

## 13. 前端替换步骤

1. 在 `src/services/agentService.js` 内把占位实现替换为 `fetch` 调用，保持函数签名：

   ```js
   buildTemplateCandidates({ selectedFeatures, customPrompt }) -> Promise<candidates[]>
   composePrompt({ store, styleId }) -> Promise<{ prompt, tips }>
   revisePrompt({ base, feedback }) -> Promise<string>
   generateImage({ prompt, seed }) -> Promise<{ dataUrl|imageUrl, provider, note }>
   reviseImage({ prompt, seed }) -> Promise<{ dataUrl|imageUrl, provider, note }>
   ```

2. 若后端返回 `imageUrl` 而非 `dataUrl`，在服务层转换为统一字段，组件无需改。
3. 增加错误态：当前 `App.jsx` 只在 busy 状态处理，建议补 `notice` 状态与重试。
4. 长任务改为轮询或 SSE，注意组件卸载时取消订阅。

## 15. Agent 资料收集（`POST /api/v1/agent/turn`）

> 状态：**契约已冻结，后端尚未实现**。前端本轮使用本地 Mock；真实 ModelArts / 盘古尚未接入。
> 完整字段、错误码与接入前待确认项见 [`agent-turn-contract.md`](agent-turn-contract.md)。

### 15.1 能力定位

这是**开店资料收集**能力，不是点餐业务接口，也不是项目/会话持久化接口：

| 对比项 | `agent/turn` | `store-projects` / `generation/*` |
| --- | --- | --- |
| 目的 | 从店主自然语言提取结构化开店资料草稿 | 项目持久化、模板匹配、提示词、生图 |
| 写入 | **店主确认前不写库** | 项目/任务持久化 |
| 身份 | 未来店主鉴权 | 店主鉴权 |
| 会话 | 单轮 `turnId`；不得复用 B1 `sessions` | 项目 ID / 任务 ID |
| 模型 | 只抽取与草拟 | 生图/对话模型 |

禁止把 B1 顾客登录的 `sessions` 表当作 Agent 会话表。若后续需要持久化，应新增 `agent_sessions` / `agent_turns` 独立表并单独立项。

### 15.2 请求与响应

- `POST /api/v1/agent/turn`，JSON，`/api/v1` 版本化。
- 请求：`contractVersion='agent-turn.v1'`、`utterance`（1–500 字）、`draft`（`ContractDraft`）、`client.surface='desktop'`、`client.phase='store-info'`、`projectId=null`。
- 响应：`contractVersion`、`turnId`、`status`（`collecting|reviewing`）、`reply`、`draft`、`missingFields`、`errors`、`nextQuestion`、`meta`。
- 金额只传 `priceCents` 整数分；`priceText` 不进入契约。
- `meta.mock=true` 时必须明确标识未调用真实模型；真实接入后 `meta.mock=false` 且 `meta.model` 为真实模型标识。

### 15.3 后端实现建议

1. 新增独立 NestJS 模块 `AgentModule`，与 B1 点餐模块解耦；路由 `POST /agent/turn`。
2. DTO 使用 `class-validator` 校验：`utterance` 长度、`draft` 嵌套字段、`priceCents` 整数与范围、菜品 0–5 道。
3. **服务端二次校验**字段与价格；不信任模型输出。最终 `readyForReview` 只作为服务端视角，前端仍会本地复算。
4. 店主确认前**不落库、不发布**；确认接口应另行设计（本轮不做）。
5. 支持 `Idempotency-Key` 与 `turnId` 去重，避免重试产生重复回合或重复计费。
6. 限流与超时：429 映射 `AGENT_RATE_LIMITED`；5xx 映射 `AGENT_HTTP_5XX`；超时建议 12s 以内由前端先取消。
7. 日志脱敏：不记录完整经营信息与模型原始输出；保留 `requestId`、耗时、模型名、错误码。
8. 模型密钥只在服务端；前端只接收短期 Token，**AK/SK 永不下发前端**。
9. Provider 适配层隔离 ModelArts / 盘古签名与响应格式；未配置 provider 时返回明确错误码，不得伪装成功。

### 15.4 验收清单

- [ ] 请求/响应字段与 `agent-turn.v1` 逐项一致。
- [ ] `contractVersion` 不匹配返回可识别错误，不静默降级。
- [ ] 价格非整数、超范围、菜品超 5 道被拒绝。
- [ ] 确认前数据库无门店/菜品写入。
- [ ] 限流、超时、5xx 有可映射错误码。
- [ ] 日志、错误体、响应中无 Token、AK/SK、堆栈与模型原始输出。
- [ ] 未复用 B1 `sessions` 表。
