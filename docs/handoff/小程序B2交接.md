## 2. 本阶段目标

只改造 `miniprogram/`：

1. 统一服务层封装 `wx.request`、Token、超时、错误归一化。
2. 按 `docs/component-contract.md` 落地核心 UI Block，组件只收 `properties`、只发 `triggerEvent`。
3. 顾客端：扫码进入门店 → 菜单 → 购物车 → 结算 → 创建订单 → 模拟付款 → 订单列表/详情 → 取消待付款订单。
4. 店主端：按 `memberships` 展示入口 → 订单工作台（10 秒轮询，离开停止）→ 状态推进 → 商品上下架。
5. 解析扫码 `scene` 的 `storeId` 与可选 `tableId`：带桌号默认 `DINE_IN`，无桌号默认 `TAKEAWAY`。
6. 形成 Base Template 候选：删除可选组件仍可完成核心闭环、仍能编译。

## 3. 建议实施顺序

严格按下列顺序，不要先写页面再回头补服务层：

### 3.1 领域纯函数

`miniprogram/domain/`：

- `money.js`：整数分格式化 `¥28.00`，禁止浮点参与计算。
- `cart.js`：合并同商品、数量 1–99、计算 `lineTotalCents` / `totalCents`（仅用于界面预览，服务端仍会重算）。
- `orderStatus.js`：六态中文文案、顾客可见性、店主可操作按钮映射。
- `scene.js`：解析 `scene` 查询参数与 `storeId/tableId`。
- `idempotency.js`：为一次结算生成并复用 Key。

这些文件应保持纯函数，可用 Node 的 `node:test` 在根目录 `test/` 下测试；不要依赖 `wx` 全局对象。

### 3.2 服务层

`miniprogram/services/`：

- `request.js`：Promise 化 `wx.request`，统一超时（建议 10s）、`Authorization`、`Idempotency-Key`、错误对象 `{ code, message, requestId }`、401 清 Token 并重新登录。
- `auth.js`：`login`（开发环境可用 `demoOpenId`）、`me`，Token 存 `wx.storage`，不写日志。
- `store.js`：`getStore`、`getCatalog`。
- `order.js`：`createOrder`、`listOrders`、`getOrder`、`demoPayment`、`cancelOrder`。
- `merchant.js`：`listMerchantOrders`、`updateOrderStatus`、`listProducts`、`updateAvailability`。

硬性要求：

- 页面不得直接 `wx.request`。
- 组件不得 `require` 服务层。
- 创建订单不传单价或总价，只传 `storeId / fulfillmentType / tableId / items / note`。
- 同一笔结算必须复用同一个 `Idempotency-Key`；失败重试不能重新生成。
- 收到 `PRODUCT_UNAVAILABLE` 刷新菜单并提示重选；收到 `AUTH_REQUIRED` / `AUTH_INVALID` 清 Token 重登。

### 3.3 组件

按 `docs/component-contract.md` 实现，目录 `miniprogram/components/<kebab-case>/`：

- 展示类：`store-header`、`category-nav`、`product-card`、`cart-bar`。
- 订单类：`order-status-badge`、`order-card`、`status-timeline`、`merchant-order-card`。
- 反馈类：`empty-state`、`error-banner`、`loading-block`。

每个组件必须有 `index.json`、`index.wxml`、`index.wxss`、`index.js` 四件套，属性有默认值，缺少数据时展示空状态而不是抛异常。

## 4. 演示登录与环境

- 本地后端 `.env`：`ALLOW_DEMO_LOGIN=true`、`ALLOW_DEMO_PAYMENT=true`、`NODE_ENV=development`。
- 小程序里用 `demoOpenId` 登录：顾客 `demo-customer-001`，店主 `demo-owner-001`，店员 `demo-staff-001`。
- 真实微信登录需要服务端配置 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`，小程序侧调用 `wx.login` 拿 `code`；未配置时后端返回 `503 WECHAT_NOT_CONFIGURED`。
- 微信开发者工具访问本地 `http://127.0.0.1:3000` 需要勾选「不校验合法域名」；真机演示需要 HTTPS 域名，属于 B4。
- 所有模拟付款界面必须出现「演示模拟支付」字样，禁止出现「微信支付成功」。
