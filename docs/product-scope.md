# 产品范围与信任边界

## 用户流程

1. 填门店基本信息，可选地选择本机图片作为风格参考。
2. 勾选必选和可选经营功能。
3. 查看功能匹配度，选择最接近的已验证页面模板；有可复用且验证通过的模块时才安全拼装，其他功能标记为待开发。
4. 选择风格，预览并逐个重生成带名称的页面图标。
5. 使用桌面内置效果预览，导出独立原生小程序工程，再用微信开发者工具检查真实运行效果。

## 生成器与门店小程序的关系

生成器是店主本机使用的 Windows 应用，不是所有门店共用的顾客小程序。导出目录是一份可单独导入微信开发者工具的源代码工程。它不会自动获得独立微信身份：店主必须使用自己的微信小程序账号，完成主体认证、配置自己的 AppID、上传代码、提交审核并发布。生成器不代办这些平台操作。

## 功能与 AI 边界

首版 AI 只推荐预先支持的风格/模板并生成图标资源。AI 不生成业务代码、不发明未验证模块、不授予店主权限。模板缺功能时选择最近模板；只有仓库内登记且通过验证的模块可以拼装，剩余功能列为待开发。未配置模型时使用明确标注的本地演示占位图和规则建议。

用户必须主动选择门店图片。云端发送前要清楚提示图片和文字将发送给当前配置的模型服务并取得确认。客户端不保存 API 密钥；服务端限制文件类型、数量和大小，不持久化参考图片。

## 当前生成器版本不包含

在线点餐后端不属于当前生成器版本，但列为后续独立里程碑：先实现演示级顾客下单与店主处理闭环，仍不包含真实支付和外送。生成器配置同步及桌面工作台云端持久化分阶段评估，具体边界见 `docs/后端实现方案与套餐.md`。本文的“当前版本不包含”不代表后端路线永久取消。

真实微信支付、外送、在线订单后台、云端自动建项目、主体/账号注册、自动上传审核发布、开放式 AI 代码生成。导出工程当前为菜单和资料展示演示模板。
